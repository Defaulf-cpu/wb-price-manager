# Веб-доступ к WB Price Manager

`tools/web-server.js` запускает тот же интерфейс и бизнес-логику, что и Electron, но через браузер. Ключи WB и данные остаются на компьютере, где работает сервер; в браузере хранится только сессия входа. Дополнительные npm-пакеты не используются.

## Рекомендуемый сценарий: HTTPS-туннель

По умолчанию (`npm run web` или `node tools/web-server.js`) сервер работает в режиме **`tunnel`**: он слушает только `127.0.0.1:8080`. Внешние подключения принимает Cloudflare Tunnel или Tailscale Serve, которые дают HTTPS-адрес и проксируют трафик на loopback. **Не настраивайте проброс порта на роутере.**

```sh
npm run web
# равноценно:
node tools/web-server.js --mode tunnel
```

Если `cloudflared` или `tailscale` доступны в `PATH`, сервер по умолчанию попробует запустить туннель сам: сначала Cloudflare, затем Tailscale. Адрес Cloudflare появится в выводе `cloudflared`; адрес Tailscale будет напечатан после настройки (его также можно узнать через `tailscale serve status`). При отсутствии обеих программ сервер не падает и остаётся доступен только на `http://127.0.0.1:8080`; консоль покажет ссылки для установки и команды ручного запуска.

При первом старте создаётся учётная запись `admin` со случайным паролем; пароль выводится в консоль **один раз** — сохраните его. Для постоянного пароля задайте `WB_WEB_PASS` или `--pass`. Cloudflare Quick Tunnel создаёт временный публичный URL: считайте его секретной ссылкой и не публикуйте.

Автозапуск можно настроить:

- `--start-tunnel` — запустить найденный туннель;
- `--no-tunnel-autostart` — оставить сервер на loopback и запустить туннель вручную;
- `--tunnel-provider auto|cloudflare|tailscale|off` — выбрать провайдера; `auto` предпочитает `cloudflared`;
- переменные `WB_WEB_TUNNEL_AUTOSTART=0` и `WB_WEB_TUNNEL_PROVIDER=tailscale` задают те же параметры.

Двойной клик по **`Веб-версия (доступ из сети).bat`** в Windows запускает именно `tunnel` по умолчанию и спрашивает, запускать ли установленный туннель автоматически.

### Вариант A: Cloudflare Tunnel

1. Установите Cloudflare Tunnel (`cloudflared`) по [официальной инструкции](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/) и убедитесь, что команда доступна в `PATH`.
2. Запустите сервер с автоматическим запуском Cloudflare:

   ```sh
   node tools/web-server.js --mode tunnel --tunnel-provider cloudflare --start-tunnel --port 8080
   ```

   Или используйте `npm run web` — при `--tunnel-provider auto` Cloudflare выбирается первым, если найден.
3. Скопируйте напечатанную ссылку вида `https://<случайное-имя>.trycloudflare.com` и откройте её на другом устройстве. HTTPS завершается на Cloudflare; приложение продолжает слушать только `127.0.0.1`.

Для ручного запуска откройте второй терминал и выполните:

```sh
cloudflared tunnel --url http://127.0.0.1:8080
```

Quick Tunnel выдаёт временную ссылку, которая меняется после перезапуска. Для постоянного домена настройте именованный туннель и DNS-маршрут Cloudflare; команду-прокси оставьте направленной на локальный адрес приложения.

### Вариант B: Tailscale Serve

1. Установите [Tailscale](https://tailscale.com/download) на компьютер с приложением и на клиентское устройство. Войдите в один tailnet и настройте его ACL.
2. Запустите сервер с автозапуском Serve:

   ```sh
   node tools/web-server.js --mode tunnel --tunnel-provider tailscale --start-tunnel --port 8080
   ```

   Сервер запускает `tailscale serve http://127.0.0.1:8080` в foreground и завершает этот процесс при остановке. Если хотите запустить Serve самостоятельно, используйте:

   ```sh
   tailscale serve --bg http://127.0.0.1:8080
   ```
3. Откройте HTTPS-адрес устройства в tailnet — обычно `https://<устройство>.<tailnet>.ts.net`. Точный URL показывает `tailscale serve status`; сервер также попытается вывести его при автоматическом запуске.

Ручная команда с `--bg` оставляет правило проксирования в конфигурации Tailscale после завершения приложения. Чтобы сбросить Serve-настройки устройства, используйте `tailscale serve reset` (команда сбрасывает конфигурацию Serve целиком, в том числе созданную ранее вручную). Роутер настраивать не нужно.

## Частные режимы

### Только этот компьютер — `local`

```sh
node tools/web-server.js --mode local --port 8080
```

Сервер слушает только `127.0.0.1`. Откройте `http://127.0.0.1:8080`. Этот режим удобен для локального использования и не открывает доступ устройствам в сети.

### Домашняя/офисная сеть — `lan`

```sh
node tools/web-server.js --mode lan --port 8080
```

Сервер слушает `0.0.0.0`, но принимает запросы только с loopback и частных адресов IPv4 (`10/8`, `172.16/12`, `192.168/16`) и IPv6 ULA (`fd00::/8`). Заголовок `X-Forwarded-For` намеренно не используется для проверки IP. Адрес для телефона показывается в консоли. Режим `lan` подходит только для доверенной сети: без сертификата HTTP не шифрует пароль и данные. Для доступа из интернета вместо LAN используйте рекомендуемый режим `tunnel`.

## Прямой режим `internet` и HTTPS

`internet` слушает внешний интерфейс (`0.0.0.0`) без фильтра по IP. Для его запуска обязательно задайте **оба** файла сертификата и ключа:

```sh
node tools/web-server.js --mode internet --port 8080 \
  --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

Также можно использовать `WB_WEB_CERT` и `WB_WEB_KEY`. Если сертификат или ключ не заданы, сервер завершится с объяснением и **не откроет порт**. Прямой режим — только для уже подготовленной HTTPS-схемы; для этой установки используйте туннель и не пробрасывайте порт роутера.

Флаг `--insecure-i-know` явно разрешает HTTP без TLS только как осознанное исключение, например для временной проверки в изолированной сети:

```sh
node tools/web-server.js --mode internet --insecure-i-know
```

Консоль предупредит об опасности, а **на каждой HTML-странице**, включая страницу входа, будет заметный баннер о незашифрованном соединении. Не используйте этот флаг для доступа через публичную сеть.

Для локального HTTPS в доверенной LAN можно использовать [mkcert](https://github.com/FiloSottile/mkcert):

```sh
mkcert -install
mkcert -cert-file lan.crt -key-file lan.key localhost 127.0.0.1 192.168.1.25
node tools/web-server.js --mode lan --port 8080 --cert lan.crt --key lan.key
```

Замените `192.168.1.25` своим LAN IP. Чтобы браузер телефона доверял сертификату, установите на него корневой сертификат mkcert. Не отправляйте приватный `lan.key` другим людям.

## Выбор кабинета WB — фиксированный профиль

```sh
node tools/web-server.js --mode tunnel --profile default
```

`--profile <id>` (или `WB_WEB_PROFILE`) выбирает **один** кабинет на весь срок работы
сервера. ID существующего кабинета виден в Electron: «Настройки → 5.1 Профили кабинетов WB».
Без параметра фиксируется текущий `activeId` регистра. Новый корректный ID создаёт пустой
профиль, поэтому проверьте ID перед запуском; опечатка не откроет случайно другой кабинет.

Все данные, ключи, резервные копии и Telegram находятся в `<dataDir>/profiles/<id>/`.
При обновлении старого каталога выполняется возобновляемая миграция в `profiles/default/`.
Перед первым запуском новой версии сохраните копию каталога данных. `web-sessions.json`
остаётся глобальным файлом корня — перенос ключей WB не переносит веб-пароль и сессии.

В браузере нельзя переключать/создавать/удалять кабинеты. Список, состояние приложения,
экспорт/импорт и P&L ограничены **только выбранным профилем**; обращение к чужому ID
отклоняется. Сервисы, планировщики и Telegram остальных кабинетов не запускаются.
Для другого кабинета остановите сервер и задайте другой `--profile`.

Корень `.data` веб-версии и каталог `userData` Electron по умолчанию различаются. Для
переноса используйте экспорт/импорт J, не копируйте отдельные рассинхронные JSON-файлы.
Без Electron `safeStorage` не применяется: резервный режим секретов — Base64, не шифрование.
Не запускайте несколько процессов автоотправки с одним каталогом данных одновременно.

## Вход, сессии и отзыв доступа

- Пользователь задаётся через `WB_WEB_USER` или `--user`; по умолчанию — `admin`.
- Пароль задаётся через `WB_WEB_PASS` или `--pass`. Если он не задан, при первом запуске генерируется случайный пароль и показывается в консоли один раз.
- Пароль хранится как scrypt-хеш с солью. Файл `.data/web-sessions.json` хранит секрет HMAC, хеш и активные сессии; права ограничиваются владельцем, где это поддерживается ОС. Не публикуйте этот файл и каталог данных.
- Сессия действует 12 часов. Cookie подписана HMAC-SHA256, имеет `HttpOnly`, `SameSite=Lax` и `Path=/`. В режиме `tunnel` cookie также помечается `Secure`, поскольку внешний адрес обслуживается по HTTPS; TLS до локального приложения завершается на туннеле.
- После пяти неверных попыток входа с одного IP на 15 минут включается блокировка. Все страницы, кроме `/login`, и все `/api/*` требуют сессию; каждый `POST /api/*` требует CSRF-заголовок.
- Кнопка **«Выйти»** отзывает текущую сессию. Для смены пароля задайте новое `WB_WEB_PASS`/`--pass` и перезапустите сервер — старые сессии будут отозваны.

## Аргументы и переменные окружения

Аргументы CLI перекрывают соответствующие переменные окружения.

| Назначение | Аргумент | Переменная окружения | По умолчанию |
|---|---|---|---|
| Режим | `--mode tunnel|local|lan|internet` | `WB_WEB_MODE` | `tunnel` |
| Порт | `--port N` | `PORT` | `8080` |
| Каталог данных | `--data <dir>` | `WB_WEB_DATA` | `<проект>/.data` |
| Кабинет WB | `--profile <id>` | `WB_WEB_PROFILE` | выбранный в регистре на момент запуска |
| Имя пользователя | `--user <name>` | `WB_WEB_USER` | `admin` |
| Пароль | `--pass <password>` | `WB_WEB_PASS` | случайный при первом запуске |
| TLS-сертификат | `--cert <file>` | `WB_WEB_CERT` | не используется в `tunnel`; обязателен для `internet` |
| TLS-ключ | `--key <file>` | `WB_WEB_KEY` | не используется в `tunnel`; обязателен для `internet` |
| Запуск туннеля | `--start-tunnel` / `--no-tunnel-autostart` | `WB_WEB_TUNNEL_AUTOSTART=0` отключает | включён в `tunnel` |
| Провайдер туннеля | `--tunnel-provider auto|cloudflare|tailscale|off` | `WB_WEB_TUNNEL_PROVIDER` | `auto` |
| Небезопасный HTTP в `internet` | `--insecure-i-know` | `WB_WEB_INSECURE_I_KNOW=1` | запрещён |
| Разрешить iframe | `--allow-framing` | `WB_WEB_ALLOW_FRAMING=1` | запрещено |
| SameSite cookie | `--samesite none|lax` | `WB_WEB_SAMESITE=none` | `lax` |

## Встраивание в iframe

По умолчанию встраивание запрещено (`X-Frame-Options: DENY`, CSP `frame-ancestors 'none'`). Только для доверенного портала запускайте с `--allow-framing --samesite none`. `--samesite none` требует HTTPS на внешнем адресе; в рекомендуемом режиме это обеспечивает Cloudflare Tunnel или Tailscale Serve.

Оба параметра ослабляют защиту от кликджекинга и отправки cookie с других сайтов. Включайте их только при необходимости и только для доверенного портала.

## Безопасность

- Не открывайте порт веб-сервера наружу через роутер. Для доступа из интернета используйте Cloudflare Tunnel или Tailscale Serve.
- Не запускайте прямой режим `internet` без сертификата: он заблокирован. `--insecure-i-know` оставьте для изолированной диагностики.
- Ключи WB и данные находятся на серверном компьютере. Пользователь с веб-доступом может выполнять действия от имени сохранённых ключей — выдавайте доступ только доверенным людям.
- Все `/api/*` требуют сессию; `POST /api/*` проверяет CSRF. Применяются CSP, `nosniff`, `no-referrer`, запрет iframe и лимит тела 25 МиБ. Для авторизованного `/api/invoke` установлен отдельный лимит 220 МиБ для импорта резервной копии до 100 МиБ.
- `X-Forwarded-For` не используется как доверенный источник IP. В режиме `lan` проверяется адрес TCP-соединения.
- `tools/serve.js` (`npm run ui`) — демо/dev-сервер без входа и этих гарантий; не используйте его для доступа из сети.

Подробности HTTP-маршрутов и каналов — в `docs/API.md`, §24. Проверка: `npm run test:web` (`tools/checks/web-server-flow.js`).

Изоляция кабинетов дополнительно проверяется в `npm run test:profiles` (137 проверок, включая настоящий HTTP-вход и запреты чужих ID).

## Обновление интерфейса

JS/CSS и общие расчёты отдаются с `Cache-Control: no-cache`; HTML содержит ревизию
`workspace-m1`, чтобы старый часовой кэш не оставил прежнее меню/налоги после обновления.
При первом переходе с прежней версии используйте Ctrl+F5. Веб-профиль остаётся фиксированным.
Светлая/тёмная тема и настройка таблицы работают и в браузере; импорт — через его выбор файла.
