# Поставка v1.3.11 — чёрное окно Electron на части видеодрайверов

Дата: 2026-11-20.

## Симптом у пользователя (продолжение истории запуска)

Окно WB Price Manager открывается, но внутри полностью чёрное: интерфейс не отрисовывается. Запуск с флагом `--disable-gpu` работает; запуск батником и собранным EXE — нет.

## Диагноз

Классический отказ аппаратного ускорения Chromium на конкретном драйвере видеокарты Windows: окно и рендерер живы, но GPU-композитинг ничего не выводит на экран — «чёрное окно». Проверено на машине пользователя сравнением запуска с `--disable-gpu` (работает) и без него (чёрный экран через батник и через установленный EXE).

Для этого интерфейса (таблицы, формы, графики без WebGL) GPU не нужен, поэтому лечение — программная отрисовка по умолчанию, а не настройка у пользователя.

## Что сделано (`electron/main.js`)

- `app.disableHardwareAcceleration()` до готовности приложения (выключается, только если не задана переменная окружения `WB_GPU=1` — возврат GPU для диагностики).

Версия также включает ранее поставленные страховки запуска: показ скрытого окна при повторном запуске и принудительный показ через 15 секунд (v1.3.9), очередь событий до загрузки окна (v1.3.10) и журнал `startup-error.log`.

## Итог проверки

- `node --check electron/main.js` — OK; `tools/version.js` — 310/310.
- `npm test` — exit 0 (2067 проверок).
- Поведение окна подтверждено на машине пользователя для ручного флага `--disable-gpu`; программный эквивалент `disableHardwareAcceleration()` — штатный API Electron для того же режима. Собранный EXE после обновления пересобирается обычным «Собрать EXE (Windows)».

## Что сделать на ПК

1. Заменить файлы проекта версией 1.3.11 (данные кабинета в `%APPDATA%` не затрагиваются), перед запуском завершить все `electron.exe` в Диспетчере задач.
2. Запустить «Запуск (Windows)» — окно должно открыться с интерфейсом.
3. Для установщика: запустить «Собрать EXE (Windows)» заново и поставить собранный EXE — он подхватит тот же режим отрисовки.
