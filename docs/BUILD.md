# Сборка Windows-приложения и автообновление

## Что нужно для сборки

- Windows x64 и Node.js LTS с npm.
- Для публикации релиза — права на создание Release в `Defaulf-cpu/wb-price-manager`.
- Иконка приложения находится в `build/icon.ico`; настройки electron-builder — в `package.json`.

Версия задаётся только полем `version` в `package.json`. Она показывается в «Настройки → Данные приложения», передаётся Electron через `app.getVersion()` и подставляется в имя установщика. При смене версии обновляйте `package-lock.json` вместе с `package.json` (команда `npm version patch`, `minor` или `major` обновит оба файла и создаст git-тег).

## Локальная сборка

В корне проекта:

```bash
npm ci
npm test
npm run dist
```

На Windows также можно запустить `Собрать EXE (Windows).bat`: он при необходимости установит зависимости через `npm ci`, по умолчанию выполнит только быстрые проверки целостности (`repo-check`) и версии, затем соберёт x64 NSIS-установщик и портативный EXE. Полный долгий `npm test` запускается явно: `Собрать EXE (Windows).bat full`. Полностью без проверок: `Собрать EXE (Windows).bat skip`. Имена в подсказке скрипта читаются из версии `package.json`, а не захардкожены.

Основные команды:

| Команда | Результат |
|---|---|
| `npm run dist` | NSIS-установщик и портативная версия |
| `npm run dist:portable` | только портативная версия |
| `npm run dist:dir` | распакованная Windows-сборка для проверки (`release/win-unpacked`), без установщика |

Выходные файлы попадают в `release/` (эта папка исключена из Git). Установщик называется `WBPriceManager-Setup-<version>.exe`, портативная версия — `WBPriceManager-Portable-<version>.exe`. В NSIS включён русский язык, можно выбрать каталог установки; создаются ярлыки в меню «Пуск» и на рабочем столе. Установщик рассчитан на установку для текущего пользователя.

В сборку включается `electron-updater` и только его необходимые runtime-модули, хотя пакет остаётся `devDependency`: web-версия и тесты не загружают его. `asar: true` упаковывает исходники приложения в архив. Каталоги `.data`, тестовые каталоги и файлы логов не включаются.

## Публикация GitHub Release

1. Прогоните `npm test` и соберите `npm run dist`.
2. Увеличьте `version` в `package.json` и согласуйте корневую версию в `package-lock.json`; версия нового релиза должна быть выше предыдущей. Создайте соответствующий тег `v<version>`.
3. Создайте **опубликованный, не черновой и не prerelease** Release в `Defaulf-cpu/wb-price-manager` с этим тегом.
4. Загрузите артефакты NSIS, которые electron-builder создал в `release/`: `WBPriceManager-Setup-<version>.exe`, его `.blockmap` и сгенерированный `latest.yml`. Если выкладываете портативную сборку, приложите её отдельным файлом; она не обновляется автоматически. Не переименовывайте файлы, на которые ссылается `latest.yml`.

Можно поручить загрузку electron-builder: настройка GitHub-провайдера уже находится в `package.json`.

```powershell
# GH_TOKEN должен быть заранее предоставлен из защищённого хранилища,
# иметь права записи Releases и не сохраняться в репозитории.
npm run dist -- --publish always
```

Публикуйте каждый новый выпуск с новой версией/тегом. Для автообновления используется публичный GitHub Release и его `latest.yml`; черновой или prerelease-релиз не следует считать каналом обновлений для пользователей.

## Как работает автообновление

В установленной Windows-сборке NSIS приложение при запуске проверяет GitHub Releases, если включён пункт «Проверять обновления при запуске» в «Настройки → Данные приложения» (по умолчанию включён). Новая версия скачивается в фоне. После загрузки приложение явно предлагает перезапуск; до этого момента можно продолжать работу. Проверку можно запустить вручную из того же раздела. Если соединения с GitHub нет, версия не найдена или загрузка не удалась, интерфейс показывает соответствующий статус; неудачная проверка не означает, что установлена последняя версия.

Автообновление предназначено для установленной NSIS-сборки. Портативный EXE собирается для совместимости с существующим сценарием запуска, но обновляйте его вручную — скачайте новую портативную версию из Release.

## Данные пользователя и удаление

Установщик заменяет файлы приложения, а не пользовательский профиль. Electron хранит профиль в каталоге `app.getPath('userData')` (точный путь показан в «Настройки → Данные приложения»); настройки, ключи, себестоимости и история не помещаются в `.data` проекта и не включаются в дистрибутив. NSIS настроен не удалять пользовательские данные даже при деинсталляции (`deleteAppDataOnUninstall: false`). Перед рискованными операциями можно скопировать весь показанный каталог профиля. Не удаляйте его при обновлении или откате.

## Подпись, SmartScreen и предупреждения Windows

Сборка сейчас **не подписывается сертификатом кода**: в конфигурации нет сертификата и закрытого ключа. Поэтому Windows может показать UAC/SmartScreen-предупреждение о неизвестном издателе или малой репутации файла — это не подтверждение вредоносности и не подтверждение безопасности. Скачивайте установщик только из Releases указанного репозитория и сверяйте версию/источник; не обходите запреты политик организации. Сертификат подписи можно добавить отдельно, но для автообновления все версии должны подписываться одним и тем же доверенным издателем и в конфигурации должен быть указан этот издатель.

При включённой подписи SmartScreen может реже предупреждать после накопления репутации издателя. Сам факт публикации на GitHub не является цифровой подписью.

## Откат на предыдущую версию

1. Если приложение ещё запускается, откройте «Настройки → Данные приложения» и выключите проверку обновлений при запуске. Дождитесь завершения текущей установки, если она уже началась.
2. Закройте приложение и сделайте резервную копию каталога профиля, путь к которому показан там же.
3. Скачайте установщик предыдущего стабильного Release `WBPriceManager-Setup-<version>.exe` из GitHub и запустите его поверх текущей установки, выбрав тот же каталог. Не удаляйте приложение через деинсталлятор перед установкой старой версии.
4. Запустите приложение и проверьте данные. Профиль пользователя остаётся на месте; если старая версия не открывает его корректно, закройте приложение и восстановите резервную копию профиля.

Если новая версия не запускается и настройку отключить из интерфейса нельзя, сначала сохраните копию каталога профиля. Затем временно отключите сеть на время установки предыдущего выпуска либо вручную установите `"autoUpdateEnabled": false` в `settings.json` внутри этого профиля; после проверки верните подключение. Это не повод удалять профиль целиком.
