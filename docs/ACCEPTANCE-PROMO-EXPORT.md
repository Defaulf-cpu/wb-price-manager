# Сверка выгрузки акции по PDF владельца

Основа: принятый M/рабочее место `e7614f0`. Это доработка импорта после получения
нового примера, а не повторное открытие заданий L/M.

## Что действительно получено и проверено

Владелец не может приложить XLSX в чат и предоставил его PDF-конвертацию
«Все товары подходящие для акции…». Просмотрены все три страницы, извлечён текстовый
слой и проверено отображение первых двух страниц. В примере 30 строк товаров;
широкая таблица разнесена по страницам **по горизонтали**. Это не три независимых
листа Excel: слева реквизиты товара, справа цены/скидки и продолжение длинного статуса.

По PDF можно проверить названия, порядок, назначение колонок и примеры значений.
Нельзя удостоверить исходный XML Excel, стили/тип ячеек, shared strings, скрытые листы
и кэш формул. Оригинал XLSX не получен и не выдаётся за протестированный файл.
PDF с товарами владельца и извлечённые данные **не добавлены в репозиторий**.

## Точные заголовки и сопоставление

| № | Заголовок в примере | Поле / использование |
|---:|---|---|
| 1 | Товар уже участвует в акции | `inAction`, `inActionKnown`: снимок флага файла |
| 2 | Бренд | `brand` |
| 3 | Предмет | `categoryName`, **не название** |
| 4 | Наименование | `title`: полное название товара |
| 5 | Артикул поставщика | `vendorCode` |
| 6 | Артикул WB | `nmID`: идентификатор товара |
| 7 | Последний баркод | Не используется как nmID |
| 8 | Количество дней на сайте | Информационная колонка; для условий РП не нужна |
| 9 | Оборачиваемость | Информационная колонка; для условий РП не нужна |
| 10 | Остаток товара на складах Wb (шт.) | `stockWb` |
| 11 | Остаток товара на складе продавца Wb (шт.) | `stockSeller` |
| 12 | Плановая цена для акции | `planPrice`: точный абсолютный порог |
| 13 | Текущая розничная цена | `price`: база до скидки из файла |
| 14 | Валюта | `currency`: в полученном примере RUB |
| 15 | Текущая скидка на сайте, % | `discount`: снимок текущей скидки |
| 16 | Загружаемая скидка для участия в акции | `planDiscount`: **не текущая скидка** |
| 17 | Статус | `fileStatus`: полный текст + распознавание участия |

Весь список заголовков хранится в результате предпросмотра и записи импорта. Значения
трёх информационных колонок 7–9 не превращаются в управляющие поля и не подменяют
текущую статистику API. Перестановка колонок не мешает распознаванию.

## Исправления

1. В прежнем парсере `Предмет` считался названием. Поскольку он расположен раньше
   `Наименование`, в заголовок товара попадала категория. Поля разделены; бренд тоже сохранён.
2. Точная колонка текущей скидки не распознавалась. Теперь текущая и загружаемая скидки
   сохраняются отдельно. Существующие краткие файлы с единственной колонкой `Скидка`
   сохраняют прежнее значение `planDiscount`; точный заголовок имеет приоритет.
3. Два склада раньше не распознавались, а отсутствующий общий остаток становился нулём.
   Теперь склады раздельные, общий остаток — сумма **двух известных** складов. Пустота
   не считается нулём; противоречивые остатки дубликатов не складываются наугад.
   В интерфейсе эти остатки подписаны как **снимок из файла**, не свежие данные API.
4. `Статус` читается и при отсутствии отдельного флага. Отрицательные «Не участвует» /
   «Не добавлен» не становятся положительными из-за подстроки «добавлен». Неизвестный
   статус остаётся неизвестным. При противоречии флага и текста — предупреждение,
   а не подтверждение участия. Полный текст файла показан отдельно от наблюдения цены.
5. Свежая скидка товаров WB, включая известные **0%**, важнее скидки на дату файла.
   Снимок файла не перезаписывается при отображении актуальных цен. Если актуальной
   цены нет, видимый запасной источник явно подписан «на дату файла»; наблюдение
   участия не выдумывается из этих запасных значений.
6. Для товара используется его `planPrice`, а не один процент календаря для всего файла.
   Загружаемый целый процент не заменяет точную цену. При другой текущей базе нужный
   процент для отображения пересчитывается от этой базы, абсолютный порог остаётся прежним.
7. Предпросмотр показывает название/предмет, обе цены, обе скидки, оба склада и статус.
   «Сохранить» по-прежнему не отправляет цены и не включает автоотправку.
8. PDF явно отклоняется как формат импорта, в том числе при переименовании в CSV.
   В нём часть nmID уже округлена до научной записи; безопасно восстановить потерянные
   цифры нельзя. Читатель XLSX берёт полное сохранённое числовое значение, а не применяет
   округляющий формат отображения Excel. Требовать повторной отправки недоступного XLSX
   в чат для проверки заголовков не нужно.
9. В этой приёмке ревизия была `promo-schema-m2`; следующая доработка использует
   `promo-board-m3`, no-cache сохранён. См. `ACCEPTANCE-PROMO-BOARD.md`.

## Что проверить на Windows

Обновить проект целиком и перезапустить; старый собранный EXE нужно пересобрать.
В своей программе выбрать исходный XLSX из кабинета WB → сверить предпросмотр →
«Сохранить» → проверить видимые товары, точные плановые цены и нужный выбор РП.
Передавать XLSX в чат для этого не требуется. Уже импортированный до исправления файл
нужно загрузить повторно в программу: прежние ошибочно сопоставленные поля из воздуха
не восстановятся.

Настоящие WB-отправки, авторизованная страница кабинета, Windows GUI/установщик и
внутренняя структура оригинального XLSX здесь не проверялись. Проверка структуры PDF
не означает автоматической поддержки PDF-импорта.
