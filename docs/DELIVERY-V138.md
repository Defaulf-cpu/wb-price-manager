# Поставка v1.3.8 — исправлена проверка целостности и диагностика запуска на Windows

Дата: 2026-11-12.

## Жалоба пользователя

На Windows сборка установщика останавливалась на быстрой проверке:

```
FAIL index.html подключает все скрипты — не подключены: src/renderer/js/views/prices.js
ИТОГ: КОПИЯ НЕПОЛНАЯ
```

А «Запуск (Windows)» не делал ничего: окно закрывалось без сообщений.

## Диагноз (два наложившихся дефекта)

1. **Наш баг из v1.3.6.** Файл раздела ручных цен `src/renderer/js/views/prices.js` удалили из приложения и из `index.html`, но забыли убрать из списка обязательных файлов в `tools/checks/repo-check.js`. На чистой копии проверка падала дважды: «не хватает prices.js» и «prices.js не подключён». В `npm test` эта проверка не входила, поэтому регрессия не ловилась.
2. **Устаревший файл на ПК пользователя.** Новая версия была распакована поверх старой папки: удалённые файлы (`prices.js`, `src/renderer/js/rules.js`) остались на диске. Поэтому у пользователя первая проверка проходила, а вторая — нет.

По запуску: `Запуск (Windows).bat` никак не проверял копию и бинарь Electron — при рассинхроне папки или повреждённом `node_modules` окно молча закрывалось.

## Что сделано

- `tools/checks/repo-check.js`:
  - `prices.js` убран из обязательных файлов;
  - добавлена проверка `REMOVED_FILES`: файлов, удалённых из проекта в новых версиях (`views/prices.js`, `rules.js` — v1.3.6), на диске быть не должно. Если найдены, проверка прямо называет файлы и способ исправления: удалить их (данные кабинета хранятся вне папки проекта, в `%APPDATA%`, удаление безопасно) или распаковать проект в новую пустую папку. Всего проверок стало 14.
- `package.json`: `repo-check.js` включён первым шагом в `npm test` — регрессия этого класса теперь ловится общим набором.
- `Запуск (Windows).bat`:
  - перед запуском выполняет проверку целостности и при проблемах показывает список и остаётся открытым (пауза), а не закрывается молча;
  - проверяет, что `electron.exe --version` реально запускается: битый/недокачанный `node_modules` даёт понятную подсказку «удалите папку node_modules и запустите снова».

## Итог проверки

- Чистая копия: `repo-check` — 14/14.
- Эмуляция наложения поверх старой папки (подложены `prices.js` и `rules.js`): проверка падает с точным списком устаревших файлов и инструкцией, код выхода 1.
- `npm test` — exit 0 (2067 проверок, включая repo-check первым шагом).
- Отпечаток версии `tools/version.js` — 304/304, версия 1.3.8.

## Что сделать на ПК с ошибкой

1. Скачать `wb-price-manager-v1.3.8-source.zip` (или `git pull`).
2. Проще всего — распаковать в **новую пустую папку**: данные кабинета лежат в `%APPDATA%` и не пострадают. Или в существующей папке `D:\Repracer\wb-price-manager` удалить `src\renderer\js\views\prices.js` и `src\renderer\js\rules.js`, затем заменить файлы проекта новой версией.
3. Если «Запуск (Windows)» после этого всё равно не открывает окно — удалить папку `node_modules` и запустить батник снова: зависимости переустановятся, а новый батник сам покажет, на каком шаге проблема.
