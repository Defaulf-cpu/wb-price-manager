# Приёмка: кабинет файла акции, Гант / Таблица акций, объединённый товар РП

Доработка поверх `84bfdcd` (сверка 17 колонок выгрузки по PDF). A–N не переоткрывались;
размерная безопасность F, самостоятельный J, Telegram K, профили L, аналитика M и
защищённый веб N сохранены. Подробный контракт: `docs/API.md` §29.

## 1. Какие решения согласованы

- **Смешанный файл:** до записи показать свои товары и исключения с причинами, затем
  сохранить только nmID текущего кабинета.
- **Полностью чужой файл:** отклонить; прежний состав, выбор и условия не удалять.
- Неизвестный/неполный/недоступный каталог не означает, что проверка пройдена или товары чужие.
- Вместо карточек акций — общий список слева; справа переключатель **«Гант / Таблица акций»**.
  В таблице строки — **акции**, не объединённый список всех товаров.
- Товары открываются из выбранной строки. Локальное **«Сохранить»** не отправляет цены WB
  и не включает автоотправку. Отправка осталась отдельным действием в репрайсере.
- В таблице РП связанные поля собраны рядом; фото/название/коды и главные настройки
  узнаваемы при горизонтальной прокрутке, как в присланном референсе.

## 2. Проверка принадлежности

Источником служит **полный ценовой каталог текущего кабинета** через официальный WB API,
а не название файла, артикул продавца, список на экране или ранее сохранённая метка.
Проверяется точный числовой **nmID**. Отсутствующий в полном каталоге nmID исключается
с причиной; разделённые списки доступны в предпросмотре, с поиском и страницами по 100.
В демо явно написано, что сверяется демонстрационный, а не реальный кабинет.

Исправлена пагинация: при отсутствии `total` WB читается до пустого массива,
`offset += limit`, до 1000 товаров на страницу. Прежние первая 1000 / предел 5000
больше не считаются полным каталогом. Защитный предел — 100 000: непустое продолжение
означает неполноту и блокирует проверку. Повтор страницы, дубли nmID, противоречивый
`total`, неправильная схема/ID и сетевой обрыв не становятся успешным полным каталогом.

Предпросмотр не записывает наборы данных. На `apply` сервер заново читает исходный файл
и проверяет его: переданный браузером список `matched` не имеет полномочий что-либо
разрешать. Контекст привязан к профилю, полному хэшу ключей, demo/sandbox и поколению
восстановления. UI передаёт контекст и отпечаток списка своих; смена состава между
preview/apply требует нового предпросмотра. Одинаковые последние четыре символа разных
ключей не смешивают клиентов. Повторное сохранение того же ключа кэш не выбрасывает.

Полный каталог переиспользуется до 2 минут в том же контексте; параллельные чтения
объединяются. Неудачный явный `force` не разрешает продолжать проверку по старому снимку.
Запоздалый ответ до нового `force` не затирает актуальный каталог и не разрешает запись.

**Ранее сохранённые файлы тоже перепроверяются** при построении состава/индекса/решений.
Чужие nmID не возвращаются в рабочий состав, выбор или план. Старый файл автоматически
не удаляется: UI показывает исключения/блокировку. При успешном сохранении выбора остаются
только свои позиции. Восстановленная из J метка `verified` не заменяет новую проверку.

## 3. Экран акций

Один и тот же компонент в самостоятельном разделе и во вкладке РП:

- слева общий список, поиск по названию/ID и фильтр периода;
- справа выбранная акция, начало/окончание, источник, файл/время проверки и счётчики;
- Гант: московские календарные дни, дни/недели, линия «сегодня», горизонтальная прокрутка;
- Таблица акций: название/ID, статус, начало, окончание, состав, выбор для РП,
  количество точных плановых цен и источник. Название и кнопка состава закреплены;
- единое выделение между списком, полосой Ганта и строкой таблицы;
- «Товары →» / двойной щелчок открывают состав; доступны импорт, CSV и локальное сохранение;
- в деталях по умолчанию видны **все** товары, отдельно остаются кандидаты и наблюдаемые
  по цене / отмеченные в файле. Длинный состав доступен через страницы, не скрытый срез;
- режим, масштаб и выбранная акция запоминаются отдельно по кабинету; поиск не переносится.

**Счётчики используют тот же состав, что окно товаров**, без подстановки всего каталога
или категории. Неизвестное значение — **прочерк**, проверенный пустой список — 0.
«Из файла», «WB API», «по скидке» различаются; оценка по скидке и частичный API не выдаются
за подтверждённый список WB. Будущий статус считается до начала, не до окончания акции.

«Цена ≤ порога» — наблюдение всех известных цен размеров во время акции до СПП.
Это не подтверждение участия WB; статус из файла остаётся датированным снимком.
Точный `planPrice`, раздельные скидки/склады и правила импорта PDF-схемы сохранены.

## 4. Таблица репрайсера

- Закреплённый **«Товар и настройки»**: фото/название, SKU/nmID, артикул продавца,
  бренд, баркод, **«Отправка в WB» и метка**.
- **«Инфо о товаре»**: категория/объём/размеры/признаки, **остаток/оборачиваемость и
  месячный план продаж** с фактом/процентом. Редакторы не дублируются.
- Четыре прежних отдельных colId (`allowSend`, `tag`, `stock`, `plan`) сохранены как
  миграционные ссылки, но отдельные широкие колонки не создаются: 28 доступных колонок.
- Сопоставление заголовков/рендереров теперь по устойчивому `colId`, не позиции массива.
  Перестановка/скрытие не подставляют цену под чужой заголовок.
- Ширины, порядок и высоты сохраняются. Старые предпочтения не удаляются; объединённые
  colId переводятся в блок-носитель. Видимость колонок теперь тоже отдельная по кабинету.
- Исправлена кнопка набора колонок: «Компактно» больше не затирается старыми чекбоксами блоков.
- Единый `data-nm`, пакетные правки/сохранение, выбор строк, фильтры и открытие карточки
  сохранены. Выключенный флаг сразу подписан «Не отправлять».
- Закрепление проверено в Chromium после реальной горизонтальной прокрутки;
  обе темы, перенос/ширина/высота, компактный и обычный режимы остались рабочими.

Исправлены две асинхронные гонки UI: запоздалое рисование старой вкладки не добавляет
второй календарь, быстрое открытие двух акций не создаёт два окна/чужое выделение.
Во время загрузки нового состава нельзя сохранить или экспортировать прежний выбор.
Ревизия ресурсов **`promo-board-m3`**, no-cache и защита веба сохранены.

## 6. Что проверить владельцу на Windows

1. Закрыть старую программу, сохранить бэкап, обновить **весь проект** (`git pull`, `npm ci`).
   Запустить `Запуск (Windows).bat`. Старый EXE нужно пересобрать через
   `Собрать EXE (Windows).bat`; скачивание исходников не меняет уже установленный EXE.
2. Выбрать правильный кабинет и загрузить его каталог. В «Акциях» найти нужную строку;
   переключить Гант / Таблица акций, проверить даты и источник.
3. Выбрать **свой исходный XLSX локально**, не PDF. В предпросмотре проверить свои/исключённые
   nmID и причины. Сохранить: в составе должны быть только свои. Для полностью чужого файла
   кнопка недоступна, прежние условия сохраняются. Повторно прикладывать XLSX в чат не нужно.
4. Открыть товары из строки, сверить точные пороги, обе скидки/склады и выбор для РП.
   «Сохранить» не должно отправить цены.
5. В РП проверить фото/коды/метку/флаг, горизонтально прокрутить таблицу; товар должен
   остаться слева. Изменить план/метку, сохранить параметры, проверить размеры/порядок и темы.

**Границы:** реальная авторизация WB/отправка цен, оригинал XLSX, установленный Electron
и GUI установщика Windows здесь не проверялись. Chromium-проверка не заменяет Windows GUI.
PDF владельца подтверждает структуру заголовков, не внутреннее устройство исходного XLSX.
Код не проверяет, что nmID подходит к конкретной акции WB: он проверяет кабинет и сохраняет
условия файла. Фактическое участие не доказывается одной только ценой/статусом снимка.
