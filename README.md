# WB Price Manager — управление ценами на Wildberries

Десктоп-приложение для Windows (Electron), которое работает с вашим кабинетом Wildberries через официальный API:

* **автоматически пересчитывает цены (репрайсер)** — 10 стратегий ценообразования, ценовой коридор «минимальная ↔ базовая», лимиты шага изменения, расписание и автоотправка цен в WB;
* **массово меняет цены и скидки** — по правилам («−5% к итоговой цене», «цена под маржу 20%», «установить скидку 35%» и т. д.) с обязательным предпросмотром;
* **контролирует условия акций** — календарь WB, состав из файла с проверкой кабинета, пороги и расчёт маржи; отдельная отправка выбранных решений из репрайсера;
* **считает юнит-экономику** — комиссия, логистика по объёму, хранение, упаковка, реклама, налог, себестоимость → прибыль, маржинальность, цена безубыточности и цена под целевую маржу;
* **защищает от ошибок** — предупредит о карантине цен WB (падение цены более чем в 3 раза), об уходе в минус и о слишком резком изменении;
* **экспортирует всё в CSV** — цены с экономикой, план переценки, список товаров по акции.

**Репозиторий проекта:** <https://github.com/Defaulf-cpu/wb-price-manager>, ветка `main`.
Как обновить свою копию, отправить изменения или дать другому агенту право на запись
через deploy-ключ — в `docs/GITHUB.md` («Способ 0»).

Пока API-ключа нет, приложение работает в **демо-режиме**: сгенерированный магазин с несколькими сотнями артикулов, 10 категориями, 6 акциями, продажами за 30 дней и демонстрационными конкурентами. Все разделы и расчёты (включая репрайсер) работают как в бою, но изменения остаются локальными. В разделе «Репрайсер» есть кнопка «Сымитировать рынок» — она меняет цены конкурентов, чтобы было видно, как репрайсер на это реагирует.

## Последнее обновление: СПП из ЛК, ABC, лесенка и явное сохранение

- **Акции WB** объединяют календарь, решения/выход, аналитику и журнал. Гант открывается
  около сегодняшнего дня МСК, текущие акции сверху; история и горизонтальная прокрутка сохранены.
  В шапке выбранной акции — **«Перейти к акции ↗»** и быстрый доступ к товарам/загрузке файла.
- **Текущая / новая цена** — компактные блоки с маржой % и прибылью ₽. Себестоимость
  и валюта рядом с товаром, прочие расходы — % **до СПП** + ₽/шт, с понятными эквивалентами.
- **СПП из официальных заказов/продаж** — дата, источник и честное «не live-витрина»;
  0% не теряется, кошелёк явно подписан моделью. **ABC 30/90/180 дней** не придумывает историю.
- **Стратегии** — отдельная библиотека механики и шаблонов; выбор в строке сразу открывает
  редактор, ⚙ открывает повторно. **Лесенка буста** считает заказы по квотам, проходит цены
  снизу вверх, выходит после последней ступени, сбрасывает день в 00:00 МСК в пределах срока.
  Из-за задержек WB ровно N заказов не гарантируется.
- **Сохранение при закрытии редактора**: ввод сначала меняется только в памяти; кнопки
  «Сохранить»/«Сохранить все» применяют его, а закрытие окна редактора РП крестиком, Escape
  или по фону также применяет локальные правки, чтобы они не терялись. Явные кнопки
  «Отменить изменения»/«Закрыть без сохранения» отбрасывают правки. Сохранение не отправляет
  WB и не включает автоматику без отдельного согласия. Сбой записи оставляет правки в памяти
  для повторной попытки, ошибка товара не мешает соседям.
- **Отдельный «Калькулятор»** в боковом меню: категория подставляет комиссию и ставки,
  все поля правятся вручную, итог показывает цену для покупателя с СПП, расходы, прибыль,
  маржу, ROI, безубыточность и цену под целевую маржу без изменения товаров. Учитываются процент
  выкупа и обратная логистика, переупаковка возвратов, брак/утери, эквайринг от цены после
  СПП, ОСНО с вычетом входного НДС, налог на прибыль и УСН 6% + НДС 5%/7%; кнопка
  «Рассчитать нужную цену» подбирает цену по целевой марже или прибыли с теми же формулами.
  Можно задать желаемую цену на полке и считать от неё.
- **Многооконная работа:** левое меню приложения сворачивается кнопкой с иконкой панели
  внизу сайдбара до узкой иконной рейки, а левая панель исходных данных калькулятора — до
  компактного блока с категорией, базовой ценой, ценой покупателя и СПП. Там же, над
  кнопкой обновления данных, находится переключатель светлой/тёмной темы. Состояния
  запоминаются; окно Electron теперь можно ужать до 760px по ширине для работы 50/50 и уже.
- Красный/жёлтый **центр ошибок** ведёт к затронутым товарам; ведущие колонки можно закреплять
  и откреплять, размеры/порядок сохраняются по кабинету. Исправлен неужимаемый переключатель темы.

**Расписание и параметры РП теперь в «Настройках».** Все семь вкладок репрайсера сохранены
как рабочие функции; боковых дубликатов цен/экономики/себестоимости нет.
Подробная инструкция, правила безопасности и ограничения:
[**docs/WORKSPACE-V4.md**](docs/WORKSPACE-V4.md).
Фактические результаты локальной приёмки этой версии: [**docs/DELIVERY-V124.md**](docs/DELIVERY-V124.md).

### Предыдущий этап: проверка кабинета, календарь акций и компактные блоки РП

**Файл акции теперь сверяется с полным каталогом текущего кабинета по nmID.**
В смешанном файле предпросмотр показывает **«Свои — сохранить» / «Исключены»** с причинами:
сохраняются только свои. Полностью чужой файл отклоняется; недоступный/неполный каталог
не выдаётся за проверку. Прежние условия при отказе не стираются. Исправлена загрузка
каталога за первой 1000/5000 товаров; старые сохранённые файлы тоже перепроверяются.

**Акции:** общий список слева, справа **«Гант / Таблица акций»**, периоды, источник и
счётчики именно выбранного состава. В таблице строки — акции; товары открываются из
выбранной строки. Неизвестные показатели — прочерки, не пустые заглушки или весь каталог.
Большой состав и оба списка предпросмотра имеют поиск/страницы. «Сохранить» по-прежнему
не отправляет цены в WB.

**Таблица РП:** флаг отправки и метка перенесены внутрь закреплённого товара с фото/кодами;
остаток и план продаж — внутрь «Инфо о товаре». Нет четырёх отдельных широких колонок.
Ширины/порядок/высоты, редактирование и темы сохранены; старые настройки колонок мигрируют,
видимость теперь отдельная по кабинету. «Компактно» больше не затирается старыми галочками.
Подробности и приёмка: [`docs/ACCEPTANCE-PROMO-BOARD.md`](docs/ACCEPTANCE-PROMO-BOARD.md).

### M и единое рабочее место

**Боковых пунктов «Цены и скидки», «Экономика», «Себестоимость» больше нет.** Их полные
функции теперь на вкладках «Репрайсера». Слева остаются панель, репрайсер, акции, отчёты,
сводка P&L, стратегии и настройки. Семь вкладок репрайсера оформлены единообразно.

В таблице **«Товары»**:
- тяните правый край заголовка, чтобы расширить колонку; двойной щелчок — по содержимому;
- тяните нижнюю границу ячейки с галочкой, чтобы увеличить высоту строки;
- переносите колонки за заголовок, строки — за маркер **⋮⋮**; «Товар» по умолчанию закреплён слева, ⌖ позволяет менять закрепление;
- «Размеры и порядок» — ручные размеры и сброс вида. Предпочтения отдельные для кабинета,
  не меняют цены/порядок отправки WB и не входят в переносимый бизнес-бэкап J;
- кнопка **«Светлая / Тёмная»** — в шапке. Границы ячеек сделаны контрастнее.

**Акции:** точная ссылка `dp-promo-calendar?action=ID` независимо от старой настройки.
Импорт Excel исправлен и на уровне IPC Electron: файл → предпросмотр → **«Сохранить»** →
товары акции. Поддержаны лист-инструкция, преамбула и распространённые варианты заголовков.
«Сохранить» в условиях акции ничего не отправляет в WB, а задаёт выбор для РП.
Участие отслеживается по текущей цене WB до СПП и порогу файла, с учётом периода и размеров;
статус «по цене» не является подтверждением состава от WB. Отправка — только из РП или
по явно включённому расписанию. Автоотправка не включается от импорта.

**M — «Репрайсер → Аналитика акций»**: локальное сравнение до/после, прогноз/факт,
возвраты, расходы, stockout и экспорт. Неполные периоды не заменяются нулями,
пересекающиеся акции не удваивают выводы. Это сравнение, не доказательство причины роста.

**Налоги:** «Настройки → Параметры РП» — НДС 22% отдельно, из цены по 22/122; для ИП —
УСН и годовые взносы отдельно, без плоского «6+1 со всей выручки». Укажите годовой доход
всего ИП и параметры уменьшения УСН; настройки проверьте с бухгалтером. Входной НДС,
налог на прибыль/НДФЛ ОСНО и полная декларация здесь не рассчитываются. Старые режимы
не переключаются молча. Подробнее: `docs/API.md` §28.

## Быстрый старт (Windows)

### Вариант 1 — просто запустить (без сборки EXE)

1. Установите [Node.js LTS](https://nodejs.org/ru/download) (версия 18 или новее).
2. Дважды кликните **`Запуск (Windows).bat`** — при первом запуске он сам выполнит `npm install` (2–5 минут) и откроет окно приложения.

### Вариант 2 — собрать установщик `.exe`

Дважды кликните **`Собрать EXE (Windows).bat`**. В папке `release/` появятся:

| Файл | Что это |
| --- | --- |
| `WBPriceManager-Setup-1.0.0.exe` | обычный установщик (ярлыки в меню Пуск и на рабочем столе) |
| `WBPriceManager-Portable-1.0.0.exe` | портативная версия — запустил и работает |

> Установщик собирается только на Windows (или на Linux/macOS с установленным Wine). Портативную папку `win-unpacked` можно просто скопировать на другой компьютер.

### Вариант 3 — посмотреть интерфейс в браузере

`Запуск в браузере (демо).bat` или `npm run ui` → откроется <http://localhost:4173>.
Это тот же интерфейс и та же логика, что в десктопном приложении, — удобно для быстрой проверки.

### Вариант 4 — веб-версия (доступ с телефона и из любой точки)

Дважды кликните **`Веб-версия (доступ из сети).bat`** или запустите `npm run web`.
Это тот же интерфейс и та же логика, но с **входом по логину и паролю**: открывать можно
с телефона в домашней сети или из интернета через туннель. Ключи WB и данные остаются
на вашем компьютере — в браузере живёт только сессия на 12 часов.

```bash
npm install
npm start          # десктопное приложение (Electron)
npm run ui         # интерфейс в браузере на http://localhost:4173 (демо/dev, БЕЗ входа)
npm run web        # веб-версия с авторизацией; по умолчанию безопасный tunnel на 127.0.0.1
npm run dist       # собрать установщик .exe под Windows
npm test           # все прогоны: лимиты, репрайсер, наблюдатель цен, веб-сервер, интерфейс
```

## Веб-версия: безопасный доступ с телефона и из любой точки

`tools/web-server.js` использует тот же интерфейс и бизнес-логику, что и Electron. По умолчанию
(`npm run web`) сервер слушает только `127.0.0.1:8080` в режиме `tunnel`; если в `PATH` есть
`cloudflared` или `tailscale`, он запускает туннель и печатает полученный HTTPS-адрес. Порт
роутера наружу **не пробрасывается**. Если утилиты нет, сервер продолжает работать локально и
печатает инструкции установки и команды ручного запуска.

Для Windows запустите **`Веб-версия (доступ из сети).bat`**: по умолчанию он выбирает tunnel,
предлагает запустить найденный туннель автоматически и напоминает про пароль. Установите
Cloudflare Tunnel (`cloudflared`) или Tailscale для доступа извне. Подробные пошаговые инструкции
— в [`docs/WEB.md`](docs/WEB.md).

| Режим | Назначение | Сетевой bind |
| --- | --- | --- |
| `tunnel` (по умолчанию) | доступ извне по HTTPS через Cloudflare Tunnel или Tailscale Serve | `127.0.0.1` — всегда loopback |
| `local` | доступ только с этого компьютера | `127.0.0.1` |
| `lan` | доступ из доверенной домашней/офисной сети; публичные IP получают 403 | `0.0.0.0` + проверка IP |
| `internet` | только для уже подготовленной прямой HTTPS-схемы | `0.0.0.0`; обязательно `--cert` и `--key` |

Режим `internet` без TLS блокируется. Флаг `--insecure-i-know` разрешает HTTP только как
осознанное исключение и выводит заметное предупреждение на каждой HTML-странице. Не используйте
его для публичного доступа. Для обычного доступа из интернета выбирайте `tunnel` и не настраивайте
проброс портов на роутере.

Вход защищён логином и паролем. Если `WB_WEB_PASS` не задан, при первом запуске генерируется
случайный пароль и печатается в консоль один раз. Пароль хранится как scrypt-хеш, сессия действует
12 часов, cookie подписана HMAC и имеет `HttpOnly`; в tunnel-cookie также включён `Secure`, потому
что внешний адрес доступен по HTTPS. После пяти неверных попыток с одного IP действует блокировка
на 15 минут. Кнопка **«Выйти»** отзывает сессию.

Все страницы, кроме `/login`, и все `/api/*` требуют сессию; `POST /api/*` проверяет CSRF. Сервер
отдаёт CSP, `X-Frame-Options: DENY`, `nosniff` и `no-referrer`; события приходят в браузер по SSE.
Ключи WB и данные остаются на серверном компьютере. `npm run ui` (`tools/serve.js`) — только
demo/dev-сервер без входа и этих гарантий; не используйте его для доступа из сети.

## Как получить API-ключ Wildberries

1. Войдите в кабинет продавца: <https://seller.wildberries.ru>
2. **Настройки → Доступ к API → Создать токен**.
3. Отметьте категории — **все нужные можно выбрать в одном токене**:

| Категория | Зачем нужна приложению | Обязательна |
| --- | --- | --- |
| **Цены и скидки** | цены, скидки, отправка изменений, календарь акций | ✅ да |
| **Статистика** | продажи и заказы за 30 дней → оборачиваемость, средняя цена, фактический СПП | желательно |
| **Контент** | названия, бренды, габариты и объём товара → точная логистика | желательно |
| **Финансы** | отчёты о реализации → фактическая логистика, комиссии, хранение, эквайринг | желательно |

4. Скопируйте токен и вставьте его в поле **«Один ключ на все разделы»** в разделе **«Настройки»**.
   Галка «Демо-режим» **снимется сама** — как только в поле появился настоящий ключ.
5. Нажмите **«Сохранить ключи и обновить данные»** — приложение сразу выгрузит из вашего кабинета
   товары с ценами, календарь акций, статистику продаж, габариты и фактические расходы.

> **Одного ключа достаточно.** Права зашиты в самом токене (битовая маска в JWT), поэтому WB
> позволяет создать один токен со всеми категориями сразу — его и нужно вставить.
> Поля отдельных ключей («Цены и скидки», «Статистика», «Контент», «Финансы») оставлены
> на случай, если права в вашем кабинете разделены между токенами: отдельный ключ имеет
> приоритет над общим. Под полями видно, какие разделы покрыты заданными ключами.

Обновить данные можно в любой момент — кнопка **«Обновить данные из WB»** в левом нижнем углу
(или «Обновить из WB» вверху на страницах «Цены», «Акции», «Экономика», «Себестоимость»).
Она перезагружает все разделы и показывает отчёт: что загружено, сколько заняло и где ошибка
(например, «у токена нет доступа к финансовым отчётам» — с подсказкой, какую категорию включить).
Ошибка одного раздела не мешает остальным: в отчёте каждый раздел помечен `✓` или `✗`,
а рядом — что именно не так и какую категорию ключа нужно включить. Если прав не хватает только
на часть статистики (продажи загрузились, заказы — нет), раздел останется зелёным, но с пометкой
«частично». Вернуться в демо можно той же галочкой в настройках, ключ при этом не удаляется.

### Проверка доступа — настоящая, а не «на глаз»

Кнопка **«Проверить доступ»** делает по одному дешёвому запросу на раздел (`limit=1`, окно в 1–2 дня)
и показывает таблицу: раздел, каким ключом он проверялся (маска), ответ WB и что делать дальше.

| Раздел | Чем проверяется |
| --- | --- |
| Цены и скидки | `GET /api/v2/list/goods/filter?limit=1` |
| Календарь акций | `GET /api/v1/calendar/promotions` на 60 дней вперёд |
| Статистика | `GET /api/v1/supplier/orders` за 2 дня |
| Контент | `POST /content/v2/get/cards/list`, `cursor.limit=1` |
| Финансы | `POST /api/finance/v1/sales-reports/list`, 1 отчёт за 7 дней |

Расшифровка ответов: **401** — токен не принят (скопирован не целиком или отозван), **403/404** —
категория не отмечена при создании токена (рядом написано, какая именно нужна), **429** — повторите
через минуту, **5xx** — сбой на стороне WB.

В демо-режиме проверка честно пишет **«не проверялось»** (жёлтым) и «запросов к WB не было» —
зелёных «доступ есть» без ключа больше не бывает.

### Сохранение ключей: пустое поле ничего не стирает

* Пустое поле при сохранении означает **«не трогать сохранённый ключ»**. Удаление — только явное:
  кнопка **«Удалить этот ключ»** под конкретным полем или **«Удалить ключи»** (все сразу).
* Под каждым сохранённым ключом видно `✓ сохранён` и его маску; в поле ключ не отображается.
* Значение с точками (`eyJhbG••••••••••cdef`) или короче 20 символов **отклоняется** — это маска,
  а не токен; в ответе оно приходит в списке `ignored`, и интерфейс объясняет это тостом.
* После сохранения интерфейс сообщает, что именно произошло: «сохранено: Финансы; не тронуты:
  Цены и скидки, Статистика, Контент».

Ключи хранятся в каталоге данных приложения и **шифруются средствами ОС** через Electron `safeStorage`; в интерфейс токен не передаётся — все запросы к WB выполняет основной процесс.
Если прочитать сохранённые ключи не удалось (сменился пользователь Windows, профиль, приложение
перенесли на другой компьютер), это **не проходит молча**: в «Настройках» появляется красный баннер
с причиной и просьбой вставить ключи заново.

Каталог данных: `%APPDATA%/wb-price-manager/` (покажет раздел «Настройки» → «Данные приложения»).
Там же — диагностика моста Electron: видно, что канал полного обновления данных разрешён.

## Как считается экономика

```
ценаWB   = базовая цена × (1 − скидка продавца / 100)
покупатель платит = ценаWB × (1 − СПП / 100)

прибыль = ценаWB × (1 − комиссия% − налог% − реклама% − эквайринг%)
          − логистика − приёмка − хранение − упаковка − себестоимость

маржинальность = прибыль / ценаWB × 100%
```

* **СПП** (скидка постоянного покупателя) компенсируется Wildberries и из выплаты продавцу **не вычитается** — поэтому в расчёте участвует цена после скидки продавца. В интерфейсе сумма, которую фактически платит покупатель, показана отдельной строкой.
* **Логистика** считается по объёму товара: `база + (литры − 1) × тариф за литр`, а для товаров крупнее порога — фиксированная ставка крупного товара. Все коэффициенты задаются в настройках, а по конкретному товару их можно переопределить в разделе «Себестоимость».
* **Комиссию WB API не отдаёт.** В приложении есть справочник комиссий по категориям (редактируется) и переопределение по каждому товару. Точные значения возьмите из отчёта о реализации в кабинете WB.
* **Себестоимость** — тоже не из API: заполняется вручную, массовой подстановкой («как доля от цены WB», «одинаковая для категории») или импортом CSV/XLSX (шаблон скачивается в разделе «Себестоимость»).

Дополнительно считаются:

* **цена безубыточности** — при какой цене прибыль равна нулю;
* **цена под целевую маржу** и **минимальная базовая цена** при текущей скидке;
* **цена под нужную прибыль в ₽**;
* **запас прочности** — на сколько процентов можно снизить цену до нуля прибыли;
* **сценарии** — «что будет с выручкой и прибылью за 30 дней, если изменить цену на X% и продажи изменятся на Y%».

## Цены и скидки: ручной ввод и массовая переценка

В разделе **«Цены и скидки»** цену можно менять двумя способами, и они не мешают друг другу.

**Вручную** — прямо в таблице, в колонках «Базовая цена» и «Скидка %». Введённое значение
сохраняется сразу и **переживает переходы между разделами** (раньше правки держались только внутри
страницы и терялись при первой же перерисовке — отсюда ощущение, что цены не сохраняются).
Количество правок видно вверху: «Изменено вручную: N».

**Массовым правилом** — панель внизу: «Применить к» (область) + «Правило» + округление + floor.

Правило по умолчанию — **«Не менять — отправить только ручной ввод»**. Это осознанное решение:
раньше по умолчанию стояло «изменить итоговую цену на −5%», и правило молча пересчитывало каждую
строку **поверх** введённого вручную значения. Теперь ручная правка всегда важнее правила:
правило применяется только к тем товарам, где цену руками не меняли.

### Кнопка отправки

«Отправить цены в WB» активна, как только в области применения есть хоть один товар. Если вы
ввели цену вручную, а область стояла на «Выбранным товарам» (галочки не ставили), приложение
**само переключит область на «Изменённым вручную»** и скажет об этом — кнопка не останется серой.

Когда кнопка всё же не активна, рядом написано почему, а в подсказке при наведении — что сделать.
В подписи кнопки всегда видно количество: «Отправить цены в WB (12)».

Отправка идёт **только через предпросмотр**: старые и новые цены, прибыль, маржа, предупреждения
(карантин WB при падении цены более чем в 3 раза, изменение больше порога, убыток, маржа ниже цели).
В WB данные уходят после подтверждения.

### Кнопка «Сохранить» — и как цена «закольцована» между разделами

Введённую руками цену сохраняет **одна кнопка «Сохранить»** (в карточке товара и в
«Цены и скидки»). Она кладёт цену в данные приложения (`pricedrafts.json`) и
**никуда её не отправляет**. В маркетплейс цены уходят только из раздела **«Репрайсер»**
(там виден весь список и предпросмотр) или кнопкой отправки в «Цены и скидки».

Что происходит после «Сохранить»:

* цена **сразу становится ценой товара во всех разделах** — экономика, репрайсер, отчёты,
  карточка товара считают уже по ней. Раньше сохранённое значение лежало мёртвым грузом,
  и прибыль с маржой продолжали считаться по старой цене;
* цена маркетплейса при этом **не теряется**: в репрайсере она в колонке «Цена на МП»,
  а ваша — в колонке «Моя цена» с разницей в ₽ и %; в карточке товара обе показаны рядом;
* **ваша цена важнее расчёта репрайсера**: при отправке в WB уйдёт она, а не предложение
  движка (тот же принцип, что и в массовых правилах: ручная правка побеждает);
* значения переживают перезапуск приложения и «Обновить данные из WB» — ничего
  не «сбрасывается по нулям»;
* строки со своей ценой помечены бейджем **черновик**, плитка **«черновик цен»**
  показывает их количество и работает фильтром;
* после успешной отправки в WB черновик по этим позициям удаляется — он уже в кабинете;
* в карточке товара кнопка **«Вернуть цену МП»** убирает свою цену и возвращает товар
  к цене маркетплейса;
* если WB не вернул цену товара (так бывает у товаров с поразмерными ценами — см. ниже),
  базовой ценой для репрайсера становится ваша сохранённая цена: сообщение «не задана
  базовая цена» при живой цене больше не появляется.

### Когда WB не отдаёт цену товара: поразмерные цены

У товаров с `editableSizePrice: true` (категории, где цена ставится отдельно на размер, а
также любой товар с включённой опцией «Разные цены для размеров») в ответе WB **нет цены на
уровне товара** — цены лежат только в `sizes[]` у каждого размера. Приложение подставляет
базовую цену из размеров и берёт **минимальную**: расчёт по худшей цене осторожнее по марже.
В репрайсере такая строка помечена бейджем **«цена по размерам»** — в подсказке видна вилка
цен и предупреждение, что отправка изменит цену всех размеров сразу.

Раньше такой товар получал нулевую базовую цену, и репрайсер писал «ОШИБКА: не задана
базовая цена», хотя в кабинете цена есть. Теперь ошибка появляется, только если цены нет ни
в WB, ни в сохранённой вручную цене, — и говорит она тогда прямо: «обновите данные из
кабинета или сохраните свою цену».

Отправка цен **по размерам** (`POST /api/v2/upload/task/size`) реализована в репрайсере.
В колонке **«Размеры»** каждой строки задаётся режим цен по размерам:

* **не трогать** (по умолчанию) — отдельная отправка размеров выключена. Если меняется
  общая базовая цена, разные цены размеров могут стать одинаковыми: интерфейс предупреждает
  об этом перед ручной отправкой, а автоотправка такого изменения блокируется;
* **синхрон** — все размеры получают цену товара; отправляются только отличающиеся от цели;
* **ручная** — нажмите **«размеры»**, выберите режим и задайте новые цены. Остальные размеры
  сохраняют свои базовые цены: общая базовая цена товара в этом режиме не отправляется.

Общий режим задаётся в **«Настройки → Параметры РП»**, индивидуальный имеет приоритет.
Правки копятся до кнопки **«Сохранить»**, затем попадают в предложение репрайсера — даже если
вы поменяли только один размер. В WB отправляет только кнопка раздела «Репрайсер».

Скидка у WB **общая для товара**, не для отдельного размера: она уходит отдельным запросом
без общей базовой цены и не выравнивает базовые цены размеров. Снижение цены размера более
чем втрое блокирует защита приложения (по умолчанию включена). Ошибки по размерам и `sizeID`
видны в общем результате отправки; количество отправленных размеров считается после фильтрации.
Если другой размер поменяли в кабинете после расчёта, перед отправкой потребуется пересчёт.

### Плитки-фильтры вместо просто цифр

Сводные плитки над таблицей — **выручка 30д, прибыль 30д, убыточных, низкая маржа,
без себестоимости, неликвид 90+, в акциях, черновик цен** — кликабельные: клик оставляет
в таблице только товары с этим признаком, повторный клик снимает фильтр. Активная плитка
подсвечена и помечена ✕. Те же плитки есть в «Репрайсере» (плюс «к отправке»), поэтому
цифры и содержимое таблицы не расходятся между разделами.

### Карточка товара — двойной клик

Двойной клик по строке (в «Цены и скидки» или в «Репрайсере») открывает окно товара
с вкладками — всё про один артикул в одном месте, без прыжков по разделам:

| Вкладка | Что внутри |
| --- | --- |
| **Экономика и цена** | цена на МП и ввод своей цены, **живой пересчёт**: прибыль, маржа, цена покупателю и Δ прибыли за месяц меняются на каждый ввод («было → станет»), ниже — полная смета на единицу с источником каждой цифры (факт WB / вручную / справочник / формула), продажи, возвраты, остатки, габариты, факт из отчёта WB и что предлагает репрайсер. Кнопка одна — **«Сохранить»** |
| **Конкуренты** | список конкурентов по артикулу: добавить, изменить цену и остаток, включить/выключить |
| **Комиссии и параметры** | личные значения товара (себестоимость, упаковка, комиссия, логистика, хранение, реклама, СПП, остаток, продажи в день) + личная стратегия репрайсера, пол и потолок цены + **калькулятор СПП по витрине** |
| **Акции** | в каких акциях товар участвует или к каким подходит, плановая цена, период, кнопка «Перейти к акции» |
| **История пересчёта** | что предложил репрайсер и что реально ушло в WB (с ценой «до»), плюс история цен |

Данные для окна берутся одним запросом (`items:card`), поэтому оно открывается сразу
и не расходует лимиты WB по каждому блоку.

### СПП: как узнать скидку покупателя

СПП — скидка, которую WB даёт покупателю за свой счёт. Официальные заказы и продажи
содержат `spp` по событию. Сохраняется последнее валидное наблюдение, включая **0%**,
источник, время события и получения. Оно не является гарантированной live-ценой для любого покупателя.

Приоритет: **ваш ручной ввод → датированное наблюдение ЛК → наблюдение витрины / среднее
продаж → настройка кабинета**. Источник виден в блоке цены и карточке; официальный
подписан «не live-витрина». Эти источники не зависят от переключателя «брать расходы из
отчёта WB» — тот про логистику и комиссию. Кошелёк задаётся отдельно и показывается модельно.

Для товара без продаж (новинка) или чтобы уточнить значение глазами — калькулятор в карточке
товара (вкладка «Комиссии и параметры»):

1. кнопка **«Подтянуть с витрины»** — приложение само прочитает карточку на витрине WB
   и подставит обе цены (если витрина не заблокировала запрос);
2. либо кнопка **«Открыть товар на витрине ↗»** — откроется карточка товара на wildberries.ru,
   и цену, которую видит покупатель, можно переписать в поле «Цена покупателю на витрине» руками;
3. СПП посчитается сам: `(1 − ценаНаВитрине / нашаЦенаСоСкидкой) × 100`;
4. **«Подставить в поле «СПП, %»»** — корректное значение сохраняется локально автоматически.

Если витринная цена оказалась выше нашей, расчёт отклоняется с подсказкой — значит открыта
не та карточка (иначе СПП получился бы отрицательным). Значение используется в цене для
покупателя, в стратегии «Удержание РРЦ», в отстройке от конкурента «с учётом СПП» и в
прогнозе СПП для решений по акциям.

Автоматическое чтение витрины (цена, СПП, остаток, конкуренты по SKU) — в разделе
[«Цены на площадке: наблюдатель витрины WB»](#цены-на-площадке-наблюдатель-витрины-wb).

### Кнопка «Обновить себестоимость»

Себестоимость вводится в разделе **«Себестоимость»**, а таблица цен строится из отдельного набора
данных. Раньше после ввода себестоимости колонка «Себест.» в ценах оставалась пустой до полного
обновления данных из WB. Теперь:

* значение подтягивается **сразу** после сохранения в «Себестоимости» — во всех разделах;
* в «Ценах» есть кнопка **«Обновить себестоимость»**: перечитывает значения из хранилища без похода
  в WB и сообщает, у скольких товаров себестоимость задана.

## Цены на площадке: наблюдатель витрины WB

API продавца отдаёт только **вашу** цену и скидку. Того, что видит покупатель, — витринной цены,
фактического СПП и остатка на витрине — в кабинете нет. Поэтому в приложении есть отдельный
модуль-наблюдатель (`electron/price-watcher.js`): он читает карточку товара на витрине WB
(`card.wb.ru`) и складывает наблюдения в `pricewatch.json`.

**Где смотреть:** карточка товара (двойной клик по строке) → вкладка **«Цены на площадке»**.

| Что даёт | Откуда |
| --- | --- |
| Цена на полке и цена покупателю | кнопка «Обновить с витрины» или ручной ввод |
| СПП, который реально видит покупатель | считается из двух цен, медиана за 7 дней идёт в экономику |
| Остаток на витрине | только с витрины (вручную не записывается) |
| Цена и остаток конкурента | по его SKU (нм-коду) — кнопка «обновить» у строки конкурента |
| История наблюдений | до 50 последних записей на товар |

### Честно про блокировки

Витрина WB защищена от ботов. Если вместо JSON приходит `403`, `429` или страница с капчей,
наблюдатель **не выдумывает цену**, а сообщает о блокировке и останавливается: повторные
запросы только усилят блокировку, поэтому до перезапуска приложения он больше не стучится.
Дальше — руками: кнопка «Открыть карточку на WB» и ручной ввод цен на той же вкладке.
Расчёты от этого не становятся менее точными, просто цифру вписываете вы, а не приложение.

### Что включено по умолчанию

* **Автозапросы к витрине выключены** (Настройки → «3.4 Наблюдатель цен витрины WB»).
  Кнопка «Обновить с витрины» в карточке товара работает и без этого переключателя —
  это один осознанный запрос, который обходит и настройку, и кэш.
* **Кэш 60 минут** — повторное обновление в пределах срока не делает новый запрос
  (в ответе видно пометку «из кэша»).
* **Не больше 200 товаров за проход**, запросы строго по очереди с паузой от 3 секунд
  и случайной добавкой — чтобы не походить на скрипт-сканер.
* **В демо-режиме запросов к витрине нет вовсе**: демо-артикулы на WB не существуют, а первый
  же отказ поднял бы блокировку, которая помешала бы настоящим запросам. Ручной ввод работает —
  на нём удобно посмотреть, как наблюдение влияет на экономику.

### Как наблюдение попадает в расчёты

Медиана СПП за последние 7 дней (не больше 50 замеров на товар) подмешивается в факты товара
как `sppPctWatch` и участвует в расчёте наравне со статистикой продаж — но **выше** неё по
приоритету, потому что это цифра «здесь и сейчас», а среднее по продажам запаздывает на окно
статистики. Ручной ввод СПП по-прежнему важнее всего.

Цена конкурента записывается как **цена покупателю (с СПП)** — именно её сравнивает репрайсер
в режиме «с учётом СПП». Если цена покупателю неизвестна (витрина отдала только цену продавца),
конкурент исключается из расчёта, а не подменяется ценой продавца: иначе отстройка получилась бы
на ровном месте. Колонка «Наш эквивалент» на вкладке показывает, какую цену до СПП пришлось бы
поставить нам, чтобы покупатель видел столько же.

Подробности устройства модуля, коды ошибок и формат файла — в `docs/PRICE-WATCH.md`,
контракты каналов — в `docs/API.md` (§23). Прогон поведения: `npm run test:pricewatch`.

## Остатки по складам WB

Остаток товара по складам теперь загружается из WB и участвует в расчёте: в репрайсере
и в карточке товара виден **остаток** и **оборачиваемость** (остаток на текущий темп
продаж), а товар, который скоро закончится, помечается бейджем **«заканчивается»**.

**Что изменилось.** Метод `GET /api/v1/supplier/stocks` **отключён Wildberries 23.06.2026**.
Приложение грузит остатки другим способом:

| Метод | Категория токена | Лимит | Назначие |
| --- | --- | --- | --- |
| `POST /api/analytics/v1/stocks-report/wb-warehouses` | **Аналитика** | 1 запрос в 20 с | **Основной.** Остатки на складах WB, офсетная пагинация, до 250 000 строк |
| `GET /api/v3/warehouses` | **Маркетплейс** | 3 запроса в 30 с | Список ваших складов (FBS) |
| `GET /api/v1/warehouse_remains` + статус + скачивание | **Маркетплейс** | задачу — не чаще 1/мин | **Запасной путь:** отчёт об остатках заданием |

Нужен ключ с категорией **«Аналитика»** (запасной путь — «Маркетплейс»). Если категории
нет, раздел «Остатки по складам WB» честно покажет, что доступа нет — а не «нет доступа
ко всему».

**Где смотреть и запускать.** Настройки → «3.5 Остатки по складам WB»: кнопки
**«Загрузить остатки»** и **«Список складов»**, порог «заканчивается» (дней, по умолчанию 14).
Загрузка также запускается из «Обновить данные из WB».

**Как ведёт себя при лимите.** Категория «Аналитика» — 1 запрос в 20 секунд. Если WB
откажет 429, раздел **уходит в фоновую догрузку** и показывает ⏳ — как статистика, а не
ошибку. И если WB ответит пустым отчётом, **предварительно загруженные остатки не
стираются** — в файле `stocks.json` остаётся прежнее состояние с отметкой о пустом ответе.

**Как остатки влияют на расчёт.** Если остатки загружены, остаток в репрайсере и
оборачиваемость берутся из WB; если нет — из ручного ввода (с пометкой источника).
Бейдж «заканчивается» появляется, когда запаса хватит меньше порога из настроек.
Остатки грузятся **одним отчётом**, а не по товарам в цикле — это и есть лимит WB.

Прогон поведения: `npm run test:stocks` (24 проверки). Контракты методов и ответов —
в `docs/API.md` (§25).

## Фактические расходы из отчёта WB

По умолчанию логистика считается по формуле (базовый тариф + за литр), а комиссия — из справочника
категорий. Это оценка: реальные тарифы WB плавающие, и они отличаются от справочных.

Поэтому приложение умеет брать **факт из ежедневного отчёта о реализации** — того самого,
по которому WB считает выплаты:

* `POST https://finance-api.wildberries.ru/api/finance/v1/sales-reports/detailed`
  (токен категории **«Финансы»**, лимит 1 запрос/мин, пагинация по `rrdId` до пустой страницы);
* старый `GET statistics-api/api/v5/supplier/reportDetailByPeriod` **отключён WB** (404) —
  оставлен только как фолбэк.

Из отчёта по каждому артикулу за окно (по умолчанию **7 дней**) считаются:

| Показатель | Источник в отчёте |
| --- | --- |
| средняя логистика на продажу | строки «Логистика», `deliveryRub`, `rebillLogisticCost` |
| средняя логистика возврата | строки «Возврат» |
| средняя комиссия, % и ₽ | `commissionPercent`, `kvwBase`, `ppvzSalesCommission` (взвешенно по выручке) |
| хранение, приёмка | `storageFee`, `paidAcceptance` |
| эквайринг, % | `acquiringFee` |
| доля возвратов, % | количество возвратов / количество продаж |

**Почему среднее за неделю.** Логистика WB зависит от объёма, веса, направления и тарифов
конкретного дня — одно значение из одного отчёта случайно завысит или занизит маржу сразу у всех
товаров. Окно в 7 дней сглаживает суточные пики, а задержка данных (отчёт публикуется раз в сутки)
для расчёта маржи не критична: расходы меняются медленно.

**Приоритет источников** — ручная настройка товара → факт из отчёта WB → справочник категории →
настройки кабинета → формула. Ручные значения факт не перекрывает: что вы указали, то и считается.
Если продаж за окно не было или отчёт не загружен — работаем по справочнику и формуле, как раньше.

Каждая цифра **помечена источником** (`fact`, `manual`, `category`, `settings`, `formula`) — видно
в расчёте репрайсера и в разделе «Экономика → Расходы», поэтому всегда понятно, откуда взялась
комиссия 22,49% и логистика 63,32 ₽.

Настройки: `useFactCosts` (использовать факт), `factWindowDays` (окно усреднения),
`factCostsPeriod` (`daily`/`weekly`), `factAutoRefreshHours` (автообновление),
`factLookbackDays` (за сколько дней искать отчёт, если за выбранные дни пусто),
`factAutoWiden` (брать последний доступный отчёт), `factMaxPages` (страниц детализации).

### «0 товаров, 0 строк» — отчёта за эти дни у WB ещё нет

WB формирует отчёты о реализации **с задержкой**: дневной появляется на следующий день,
недельный — в понедельник за прошлую неделю. Поэтому в середине недели запрос за «последние
7 дней» может вернуть ноль строк — это не ошибка ключа и не сбой приложения.

Раньше такой ответ показывался как успех: `✓ Фактические расходы — 0 товаров, 0 строк (0.1 с)`,
и экономика молча оставалась на справочнике. Теперь:

1. приложение сообщает, что за период отчёта нет, и **почему** (даты, какой период отчёта запрошен);
2. запускает фоновый поиск: спрашивает у WB список отчётов (`sales-reports/list`) за
   `factLookbackDays` дней, берёт последние сформированные (при отсутствии дневных пробует
   недельные) и грузит их детализацию;
3. подписывает результат: **«взят последний доступный отчёт WB»** — в «Отчётах» появляется бейдж
   с запрошенным и фактическим периодом, в «Настройках» видны `reportId` и даты отчётов;
4. **сохранённые ранее расходы не стираются**, пока не пришли новые строки.

То же самое можно сделать вручную: кнопка **«Найти последний отчёт WB»** в разделах «Отчёты»
и «Настройки → 3.1 Фактические расходы». Она терпеливая: лимит WB — один запрос в минуту,
поиск со списком отчётов и детализацией занимает одну-две минуты.

## Лимиты WB API: что грузится сразу, а что в фоне

У WB разные потолки частоты для разных категорий, и два из них жёсткие:

| Категория | Лимит WB | Что это значит на практике |
| --- | --- | --- |
| Цены и скидки, Календарь акций, Контент | 10 запросов / 6 с | грузятся сразу, паузы выдерживаются автоматически |
| **Статистика** | **1 запрос / минуту** | продажи — одна минута, заказы — ещё одна |
| **Финансы** | **1 запрос / минуту** | список отчётов — минута, каждая страница детализации — минута |

Поэтому «Обновить данные из WB» устроено так:

* товары, акции и карточки грузятся сразу;
* **статистика — одним запросом** (продажи). Заказы догружаются в фоне через минуту отдельным
  запросом: так кнопка не висит две минуты, а поле «Заказы, шт» всё равно заполняется.
  Отключить — настройка `statsLoadOrders`;
* **отчёт о реализации — одним запросом** за выбранный период; если строк нет, поиск последнего
  отчёта уходит в фон (см. выше);
* раздел, упёршийся в лимит (`HTTP 429`), **не показывается ошибкой**: он помечается ⏳
  с временем автоматического повтора и кнопкой «Повторить сейчас». Когда данные придут,
  приложение само сообщит об этом и перерисует раздел — нажимать что-либо не нужно;
* уже загруженная статистика **не стирается**, если WB ответил 429: в сообщении так и написано —
  «Ранее загруженные данные (N товаров с продажами) остались на месте».

Состояние фоновых задач и лимитов видно в **«Настройки → 3.2 Статистика продаж и лимиты WB»**:
сколько товаров загружено, догружены ли заказы, какие разделы ждут своей минуты и сколько секунд
осталось до следующего запроса по каждой категории.

Технические детали (каналы `data:deferred`, `data:refresh-section`, `stats:orders`, `stats:state`,
`wb:rate-state`, заголовки `X-Ratelimit-Retry` / `X-Ratelimit-Remaining`) — в
[`docs/API.md`](docs/API.md), разделы 2, 5.1, 15.

## Отчёты: P&L и динамика

### Выбор периода

Отчёт строится не только по последнему загруженному снимку: в разделе «Отчёты» есть поля
**«Период с / по»**, кнопка **«Показать за период»** и быстрые пресеты — 7/14/30/90 дней,
этот месяц, прошлый месяц, этот год.

* под выбранный диапазон отчёт WB дочитывается (лимит категории «Финансы» — 1 запрос в минуту,
  поэтому загрузка может занять минуту-две);
* просмотр периода **не перезаписывает** основной снимок расходов — экономика остальных разделов
  остаётся на актуальных данных;
* если WB ещё не сформировал отчёт за эти даты, приложение ищет последний доступный и подписывает
  «взят последний доступный отчёт WB» с фактическими датами;
* кнопка «Вернуться к загруженному отчёту» снимает выбранный период.

Раздел **«Отчёты»** — это ответ на вопрос «сколько я реально заработал». Раньше загрузка отчёта
о реализации только пересчитывала расходы внутри экономики, а самих цифр отчёта видно не было.

Отчёт строится из загруженного финансового отчёта WB («Настройки» → «Загрузить фактические
расходы», или кнопка загрузки прямо в разделе «Отчёты») и состоит из четырёх вкладок:

| Вкладка | Что показывает |
| --- | --- |
| **Сводка P&L** | полный разбор выручки до чистой прибыли + структура расходов + что требует внимания |
| **По дням** | динамика продаж, выручки и удержаний по датам отчёта |
| **По категориям** | прибыль и маржа в разрезе категорий, с итогами |
| **По товарам** | P&L каждого артикула: выручка, комиссия, логистика, себестоимость, прибыль, маржа |

### Порядок статей — почему «к перечислению» не равно «выручка минус всё»

```
выручка − комиссия − эквайринг                    = к перечислению от WB (ppvz_for_pay)
к перечислению − логистика − хранение − приёмка − штрафы = после расходов WB
после расходов WB − себестоимость − упаковка − реклама − налог = чистая прибыль
```

WB считает `ppvz_for_pay` как выручку минус комиссию и эквайринг, а логистику, хранение, приёмку
и штрафы выставляет **отдельными строками** отчёта. Если вычесть их до «к перечислению», получится
двойной счёт — именно так первая версия отчёта завышала прибыль на сумму логистики и хранения.

Верхняя часть (до строки «После расходов WB») — **факт из отчёта WB**. Себестоимость, упаковка,
реклама и налог — **ваши данные**: WB их не знает, они берутся из раздела «Себестоимость»
и настроек. Если у товара не указана себестоимость, отчёт об этом предупреждает: прибыль по таким
товарам завышена, и рядом показано, сколько их.

Любой отчёт выгружается в CSV одной кнопкой.

## Акции: переход в кабинет и ошибка «HTTP 422»

**Кнопка «Перейти к акции ↗»** (в карточке акции, в окне акции и в карточке товара) открывает
кабинет WB в браузере. Там файл состава скачивается так: открыть акцию в «Календаре акций» →
**«Перейти к товарам для акции» → «Сформировать» → «Скачать»**. Затем возвращаетесь в
приложение и загружаете файл кнопкой «Загрузить товары из файла».

WB не публикует прямой адрес конкретной акции, поэтому ссылка задаётся шаблоном в
**«Настройки → 3.3 Акции: переход в кабинет WB»** (подстановки `{id}` и `{name}`). Если WB
введёт постоянную ссылку — достаточно поправить адрес, ничего переустанавливать не нужно.

### Состав акции — из файла, к WB за ним не ходим

Метод состава акции у WB помечен **«Not applicable for auto promotions»** и отвечает
`HTTP 422: Unprocessable entity` почти на любой акции — ни кандидатов, ни участников он
фактически не отдаёт. Поэтому приложение **по умолчанию не запрашивает состав через API вовсе**.

Источники состава по приоритету:

1. **файл из кабинета** — точный состав с плановой ценой (кнопка «Загрузить товары из файла»);
2. **вывод по вашим товарам** — WB сообщает факт скидки и плановую цену, но не название акции;
   товар со скидкой ≥ требуемой удовлетворяет условиям акции, поэтому считается участником;
3. **API** — только если включить «Настройки → Запрашивать состав акции у WB» (по умолчанию выключено).

Каждая строка состава помечена источником: `из файла кабинета` / `по факту скидки` / `из WB API`,
чтобы вывод по скидке не выглядел точными данными WB.

Окно акции больше **не показывает сырых ошибок WB**: вместо них — плашка с источником состава
и кнопками «Перейти к акции в кабинете WB» и «Загрузить товары из файла». Если состава нет,
написано, что именно сделать.

В самом окне по каждой строке видны **цифры из вашего файла**: плановая цена WB и плановая
скидка, плюс базовая цена, скидка сейчас, сколько не хватает до порога, цена в акции,
прибыль и маржа «сейчас → в акции», Δ прибыли, остаток, продажи за 30 дней, вердикт
(«можно входить» / «ниже цели» / «убыток») и решение репрайсера. Отдельная колонка
**«Источник»** показывает, откуда взята строка: `из файла` / `по скидке` / `из WB API` /
`не загружен`.

Дополнительно:

* одинаковые предупреждения не повторяются чаще раза в 8 секунд — вместо десятка тостов
  одна сводная плашка;
* индекс акций кэшируется на 15 минут, поэтому переход между разделами не дёргает WB
  (лимит календаря — 10 запросов за 6 секунд);
* пустое поле из «деталей» акции не затирает её тип: иначе автоакция теряла признак `auto`,
  и приложение снова лезло за составом, получая тот самый 422.

**Где видно, в каких акциях товар уже участвует** — в карточке товара (двойной клик по строке
в «Цены и скидки» или «Репрайсер») на вкладке «Акции»: акция, тип, требуемая скидка, плановая
цена, статус участия и источник этих данных.

## Акции: ручная загрузка состава из файла

Календарь акций WB по API отдаёт состав не всегда, а **автоакции через API не управляются вообще**.
Поэтому состав акции можно загрузить файлом — так же, как это сделано в INDEEPA:

1. Раздел **«Акции WB»** → карточка нужной акции → **«Загрузить товары из файла»**
   (та же кнопка есть внутри окна товаров акции).
2. Выберите файл из кабинета WB: календарь акций → нужная акция → «Настроить список товаров» → скачать.
   Поддерживаются **XLSX и CSV** (разделитель `;` или `,`).
3. Приложение покажет, сколько товаров распознано, какие колонки оно поняло и первые строки —
   чтобы было видно, что файл прочитался правильно.
4. Дальше репрайсер работает с этими товарами как с полученными по API: считает вход, выход,
   плановую цену и экономику.

Колонки распознаются по заголовкам: «Артикул WB» / `nmID`, «Артикул продавца», «Наименование»,
«Цена до скидки», «Плановая цена», «Скидка», «Участвует». Если заголовков нет, приложение само
найдёт колонку с артикулами WB (длинные числа). Строки без артикула пропускаются, их количество
показывается в отчёте об импорте. Файл без артикулов WB отклоняется с понятной ошибкой.

Загруженный список **дополняет** данные API, а не заменяет их: плановая цена из файла применяется
только там, где API её не отдал. Список сохраняется в данных приложения и переживает перезапуск;
на карточке акции видно «✓ из файла загружено N товаров» с именем файла и временем. Удалить список
можно в том же окне.

XLSX читается собственным парсером (`electron/xlsx-lite.js`, ZIP+XML на встроенном `zlib`) —
внешние библиотеки не нужны, приложение работает офлайн.

## Репрайсер — автоматический пересчёт цен

Раздел **«Репрайсер»** пересчитывает цены по вашим правилам и показывает отчёт «было → станет» с прибылью, маржой и прогнозом изменения прибыли за месяц. Отправка в WB — только после подтверждения (или автоматически, если включить автоотправку).

### Одно рабочее место: семь вложенных вкладок

Всё, что раньше требовало перехода в другой раздел, теперь открывается прямо в репрайсере:

| Вкладка | Что внутри |
| --- | --- |
| **Товары** | таблица цен и предложение репрайсера, правки на месте, панель инструментов (Пересчёт · Обновить цены · Excel · CSV · Импорт · Отменить · Сохранить · Колонки · Плотность · Сегменты · Поиск) |
| **Массовые правила** | правило переценки целиком: область применения, тип, значение, округление, минимальная цена и обязательный предпросмотр; ниже — массовые параметры товаров |
| **Себестоимость** | та же таблица, что в разделе «Себестоимость»: заполнение в строке, массовое заполнение, импорт **CSV или XLSX**, шаблон, экспорт |
| **Конкуренты** | конкуренты по SKU: добавление, правка, удаление и кнопка «С витрины» |
| **Цены и скидки** | ручные цены/скидки и локальные черновики, предпросмотр и импорт |
| **Экономика** | единые расходы, прибыль, маржа и обратные расчёты |
| **Журнал изменения цен** | история предложений, передачи и подтверждённой установки |

Акции, аналитика и журнал участия — в **«Акции WB»**; расписание и параметры — в **«Настройки»**.

Старые разделы никуда не делись и работают как раньше — репрайсер просто показывает те же
панели у себя. Общий движок массовых правил (`src/renderer/js/rules.js`) используется и в
«Ценах и скидках», и здесь, поэтому одинаковые настройки дают одинаковый план. Из вложенных
вкладок **в WB ничего не отправляется**: правила кладут цены в черновик, а отправка —
отдельной кнопкой на вкладке «Товары».

### Одна страница: текущие цены, предложение и правки

Вкладка **«Товары»** (идентификатор `prices` сохранён; раньше называлась «Цены и стратегии»)
объединяет то, что было разнесено по «Новые цены» и «Товары и стратегии»:

* **цена сейчас** (база, скидка, цена со скидкой) и **новая цена** репрайсера — в одной строке,
  рядом изменение в ₽ и %, прибыль и маржа «до → после», прогноз Δ прибыли за месяц;
* **стратегия** и **минимальная цена (пол)** редактируются прямо в строке — сохранение
  и пересчёт происходят на месте, переключаться никуда не нужно;
* сверху — плитки-фильтры (те же, что в «Цены и скидки») и поиск;
* при входе в раздел цены **пересчитываются сами**: текущие и предложенные цены видны сразу,
  без обязательного нажатия кнопки;
* двойной клик по строке открывает карточку товара, кнопка «почему» — объяснение цены по слоям.

Блок **«Массовые параметры товаров»** (на вкладке «Массовые правила») — всё, что влияет на расчёт, в одной таблице:
**себестоимость**, упаковка, комиссия %, логистика ₽, минимальная цена, целевая и минимальная
маржа, РРЦ, план продаж, целевая оборачиваемость, защита от out-of-stock, разрешение
отрицательной маржи, стратегия. Незаполненная себестоимость помечается «не задана» —
такой товар репрайсер **не предложит к отправке**.

Значения общие с разделом «Себестоимость» (один файл `costs.json`): изменив здесь, вы меняете
их и там, а экономика пересчитывается во всех разделах сразу. Раздел «Себестоимость» остался
для массового заполнения — импортом CSV или одним значением на всю категорию.

### Как устроена строка товара (по образцу INDEEPA)

Страница сделана по образцу репрайсера INDEEPA: всё про товар — в одной строке, правки на месте.

| Колонка | Что показывает |
| --- | --- |
| **Выгодность** | `Супер-выгодный` / `Выгодный` / `Невыгодный` / `Без индекса` — по марже относительно целевой и минимальной. «Без индекса» означает, что себестоимость не задана и оценить выгодность нельзя |
| **Товар** | фото или заглушка, название, `SKU … · артикул`, бренд. Двойной клик по строке открывает карточку товара (по самому полю ввода — нет); на второй и следующих страницах открывается именно тот товар, по которому кликнули |
| **Ошибки в строке** | красная подпись вида «ОШИБКА: не задана себестоимость; не задан порог минимальной цены» — **в ячейке «Стратегия»**; такие товары **не предлагаются к отправке**. Себестоимость 2 ₽ и меньше не проходит даже при сохранённой вручную цене: это проверяет сервер |
| **Стратегия** | выпадающий список и поле себестоимости: меняются прямо в строке, запись и пересчёт — после «Сохранить» |
| **Цена сейчас / Цена покупателю сейчас** | база, скидка %, цена со скидкой и цена с учётом СПП |
| **Новая цена / Цена покупателю станет** | то же для предложения репрайсера + изменение ₽ и % |
| **Акции** | решение (Войти / Выйти / Участвуем / Выгодно войти / Не входим / Убыточно) и по каждой акции: период, минимальная цена, цена входа, маржа в акции и маржа ₽, «сейчас → будет» |
| **План продаж** | план на месяц и % выполнения; если план не задан — «⚪ План не заполнен, % выполнения не рассчитан» |
| **Пол / потолок** | оба порога редактируются в строке — минимальная цена и базовый (`basePriceTarget`), рядом показан рассчитанный коридор |
| **Конкурент** | лучший конкурент (цена и имя), остальные списком: **SKU, остаток, цена, цена с СПП, цена с WB-кошельком**; кнопка **«+ конкурент»** добавляет прямо из строки |
| **Отстройка от конкурента** | тип цены конкурента (`цена как есть` / `с учётом СПП` / `СПП + кошелёк`), величина отступа и **его тип — % или ₽**, выбор конкретного SKU («учитывать SKU»). Сохраняется в личных настройках товара и сразу пересчитывает цену |
| **Остаток / оборачиваемость** | штуки и дни |

У конкурента хранится **SKU (нм-код его карточки на витрине)** — по нему наблюдатель цен
сможет сам обновлять цену и остаток. Цена конкурента показывается в трёх видах: как есть,
**с СПП** и **с WB-кошельком** (`цена / (1 − СПП/100)` и далее `/ (1 − кошелёк/100)`) —
потому что WB показывает покупателю цену с СПП, и сравнивать надо одинаково. Те же формулы
использует движок при отстройке, поэтому цифра в колонке и цена расчёта не расходятся.

Отступ в рублях применяется **после** приведения цены конкурента к выбранному типу
(например, при СПП 20 % цена на полке 1000 ₽ превращается в 1250 ₽, и уже от них считается
«минус 100 ₽»). Цена никогда не уходит в минус.

### Отменить / Сохранить — правки копятся

Изменения в строках (стратегия, минимальная цена, отстройка от конкурента, себестоимость,
упаковка, комиссия, логистика, план, РРЦ, чекбоксы) **не улетают в хранилище по одной**.
Они копятся, строка подсвечивается жёлтым, а над таблицей появляется панель
«Несохранённых изменений: N» с кнопками **«Сохранить»** и **«Отменить»** — как в INDEEPA.

Раньше каждая правка ячейки запускала полный пересчёт по всем товарам: пять изменений —
пять пересчётов подряд. Теперь на пачку правок — одна запись настроек, одна запись расходов
и **один** пересчёт. «Отменить» возвращает значения из хранилища и ничего не пишет.

Таблицы разбиты на страницы со счётчиком «1 - N из M»: **«Товары» — по 100 строк**,
«Параметры товаров» — по 100. Тысячи строк с десятками полей ввода тормозят и браузер, и
отрисовку; при пустой выборке счётчик честно показывает «0 - 0 из 0». Расчёт и выгрузка
при этом всегда идут по **всем** товарам, а не по текущей странице.

**Таблица «Товары» — как лист Excel в INDEEPA.** Колонки собраны в блоки: «Артикул»,
«Инфо о товаре», «Текущая цена», «Новая цена», «Мин цена (в акции)», «Цена (вне акции)»,
«Себестоимость и экономика», «Конкуренты». Шапка из двух рядов — сверху название блока,
снизу колонки; оба ряда и выбранные ведущие колонки закреплены при прокрутке. Кнопка **«Колонки»**
включает и выключает блоки целиком или отдельные колонки (12 объединённых колонок),
выбор запоминается. Себестоимость, план продаж, метка товара и флаг «Отправка в WB»
редактируются прямо в строке — проваливаться в карточку не нужно. Себестоимость можно вести
в валюте (CNY, USD, EUR, TRY и др.): курс задаётся на вкладке «Параметры», а сумма в рублях
считается на лету; если курс не задан, строка честно блокируется с подписью, какой валюты
не хватает.
Несохранённые правки не теряются ни при перерисовке, ни при смене страницы: поля рисуются из
очереди правок, а не только из хранилища.

**Импорт CSV** в панели товаров лишь добавляет правки в очередь (колонки `нм-код`/`nmID`,
стратегия, минимальный и базовый пороги; неизвестные товары пропускаются). Корректные
правки нужно подтвердить кнопкой «Сохранить»; отправка WB остаётся отдельным подтверждённым действием.

**Фильтр-сегменты** вместо набора чекбоксов: `Все · К отправке · Своя цена · Ошибки данных ·
Убыточные · С предупреждениями`. Активен один признак, рядом написано, сколько товаров
отобрано. «Своя цена» показывает товары с сохранённой вручную ценой, «Ошибки данных» —
те, что не уйдут в WB из-за незаполненной себестоимости или порогов.

**Плотность строк** переключается («Обычные» / «Плотные») и запоминается: в плотном режиме
на экран входит примерно вдвое больше товаров — при 21 колонке это заметно.

**Массовые параметры**: выделите строки галочками — в панели снизу можно назначить всем
сразу стратегию и минимальную цену или сбросить их личные настройки. Правки копятся
и применяются одним пересчётом.

Колонок в таблице цен 21, поэтому их видимость настраивается кнопкой **«Колонки»**: по
умолчанию показано всё нужное (скрыт только «Коридор» — он дублирует «Пол / потолок»), есть
готовый **«Компактный набор»** из 10 колонок для небольшого экрана и **«Все колонки»**.
Выбор запоминается и переживает перезапуск. Товар, цена сейчас, новая цена, изменение и
кнопка «почему» показаны всегда — их выключить нельзя.

Выгрузка — **CSV** (быстрый путь, без ограничения строк) и **Excel до 150 000 строк**
(кнопка «Excel (до 150к строк)»). XLSX собирает собственный писатель без зависимостей
(`electron/xlsx-write.js`): ZIP и CRC32 пишутся вручную, строки хранятся в `sharedStrings.xml`,
а числовой ячейкой становится только настоящее число. Поэтому артикул `00123` не теряет ведущие
нули, длинный числовой SKU не теряет разряды, а текст, начинающийся с `=`, не превращается в
формулу. Файл проверяется round-trip: то, что записали, читается обратно нашим же парсером,
включая спецсимволы, перевод строки внутри ячейки и пустые ячейки; отдельно проверена выгрузка
150 000 строк (≈3,3 МБ за ~3,4 с).

Сверху — сводка (пересчитано, к отправке, Δ прибыли за месяц, Δ выручки, предупреждения),
время расчёта, время отправки **данного** предложения и число устаревших позиций, а также
плашка «Не вошли в предложение: N товаров с незаполненными данными» с примерами и подсказкой,
где заполнить.

Отправить можно всё предложение или только выбранные строки. Обе кнопки спрашивают
подтверждение и заблокированы, пока параметры не сохранены; частичная отправка идёт через тот
же канал `repricer:proposal-send` с проверкой, что цены в WB не уехали, а неотправленные
позиции остаются в предложении.

### Журналы

* **«Журнал изменения цен»** — что предложил репрайсер (фаза «предложено») и что реально ушло
  в WB (фаза «отправлено»): когда, товар, было → стало, изменение в ₽ и %, стратегия, причина.
  Одинаковые записи из двух хранилищ схлопываются.
* **«Журнал участия в акциях»** — постоянная история: **вход в акцию**, **выход из акции**
  и **возврат цены** после окончания автоакции. По каждому событию: когда, товар, акции,
  цена «до» и «после», причина решения и признак неудачи, если WB не принял изменение.
  Незакрытые позиции (цена ещё держится повышенной) дополнительно помечаются статусом
  «держит автоакция» / «ждёт вывода» / «готов к возврату».

История хранится отдельно от очереди возврата: очередь очищается, как только цена возвращена,
а журнал остаётся — иначе вкладка пустела сразу после возврата.

В обоих журналах: поиск по артикулу/нм-коду/названию, фильтр по датам, экспорт **CSV и Excel**,
двойной клик по строке открывает карточку товара. Оба формата собираются из одного набора
строк, поэтому не расходятся по колонкам. На экран выводится первая 1000 событий, а выгрузка
забирает всю выборку — до 150 000 событий, а не только видимые строки.

### Две фазы: сначала показать, потом отправить

Автопересчёт **не затирает** установленные цены — он работает в две фазы:

1. **Фаза 1 — расчёт** (по умолчанию каждые 40 минут). Репрайсер считает цены и сохраняет
   *предложение*: в интерфейсе появляется панель «Репрайсер хочет изменить N цен» с временем
   расчёта. Цены в кабинете не меняются.
2. **Фаза 2 — отправка** (по умолчанию через 40 минут после расчёта). Если автоотправка
   включена, предложение уходит в WB. Перед отправкой цены перечитываются из кабинета:
   позиции, которые изменились без приложения, **пропускаются** и показываются списком —
   чужие правки не затираются, а предложение помечается устаревшим, если изменилось всё.

Отправить или отклонить предложение можно в любой момент вручную — кнопки в той же панели.
Автоотправка по умолчанию **выключена**: сначала видно, что хочет сделать репрайсер.
Настройки — в **«Настройки → Расписание РП»** (интервал пересчёта, задержка отправки,
двухфазный цикл, автоотправка).

По каждому артикулу сохраняется история: что было предложено (`propose`) и что реально
передано (`submitted`) и подтверждено применённым (`send`) — видно в карточке товара
на вкладке «История пересчёта». Принято на обработку не означает установку.

### Как устроен расчёт (три слоя)

| Слой | Что делает |
| --- | --- |
| **1. Стратегия** | считает целевую цену: по конкурентам, по марже, по плану продаж, по оборачиваемости, по РРЦ или AI-подбором |
| **2. Верхнеуровневые ДЦО** | защитные правила поверх стратегии: защита от out-of-stock, повышение акционной цены, распродажа неликвида. Если сработало несколько — берётся **максимальная** цена |
| **3. Красивая цена** | всегда последней: округляет итог до …9 / …90 / …99 ₽ (ближайшая, слегка вниз/вверх, максимум вниз/вверх) |

После этого цена загоняется в **ценовой коридор** (минимальная ↔ базовая), ограничивается **шагом за одно обновление** (по умолчанию 19%) и **суточным лимитом**, проверяется на **карантин цен WB** (падение более чем в 3 раза) и переводится в пару «цена до скидки + скидка %».

### Стратегии

| Стратегия | Логика |
| --- | --- |
| **По умолчанию** | сравнивает базовую, акционную и цену конкурента; если акция/конкурент внутри коридора — берёт наименьшую, иначе ставит базовую |
| **Целевая маржинальность** | подбирает цену, при которой маржа равна целевой (режим расчёта маржи: от цены со скидкой / от суммы ForPay / от цены с кошельком) |
| **Конкурентный приоритет** | идёт за минимальной ценой включённых конкурентов, у которых товар в наличии; ниже минимального порога → порог, выше базовой → базовая; конкурента нет → «По умолчанию» |
| **План-факт** | план продаж на текущий месяц: отстаём от графика → снижаем цену, опережаем → повышаем |
| **Оборачиваемость** | держит целевую оборачиваемость: запас выше цели → снижаем, ниже → повышаем |
| **Удержание РРЦ** | цена для покупателя не должна опускаться ниже РРЦ (с учётом СПП и WB-кошелька) |
| **AI-подбор цены** | перебирает цены в коридоре и выбирает ту, что даёт максимум прибыли при текущем темпе продаж (эластичность спроса настраивается) |
| **Акция** | цена под акцию с проверкой минимальной маржи в акции |
| **Держать цену** | цена не меняется (товар исключён из пересчёта) |
| **Лесенка буста** | дневные квоты заказов по проверенным порогам акций, повышение ступени и безопасный выход |

### Настройки

* **общие** — в разделе «Настройки», на двух вкладках: «Расписание РП» (пересчёт ежечасно / каждые N минут / раз в сутки в выбранный час, двухфазный цикл, задержка отправки, автоотправка цен, история запусков) и «Параметры» (режим расчёта маржи, разрешение менять цену до скидки, разрешение отменять скидки, лимиты шага, поведение в акциях, значения по умолчанию для новых товаров);
* **по артикулу** (двойной клик по строке или кнопка «настроить»): стратегия, минимальная и базовая цена коридора, целевая и минимальная маржа, РРЦ, план на месяц, целевая оборачиваемость, защита от out-of-stock, красивая цена — с живым предпросмотром итоговой цены и разбором по слоям;
* **массово**: назначить стратегию, маржу и минимальную цену (в том числе «= цена безубыточности») сразу всем отобранным товарам; есть экспорт и импорт CSV;
* **конкуренты**: список конкурентов по артикулу — вручную, импортом CSV или кнопкой **«С витрины»** (один разовый запрос к витрине WB; если витрина закрыта — честный статус «заблокировано, введите вручную», а не выдуманная цена). Автозапросы по умолчанию выключены.

> **Важно про конкурентов.** Официальный API Wildberries **не отдаёт цены конкурентов** в карточке товара, поэтому их источник — вы сами: ручной ввод, CSV из вашего сервиса аналитики (MPStats, MarketGuru и т. п.) или парсер. В демо-режиме конкуренты сгенерированы, и есть кнопка «Сымитировать рынок», чтобы посмотреть, как репрайсер реагирует на изменение цен.

### Кнопка «почему такая цена»

Для любого товара видно полное объяснение расчёта: каждый слой с правилом, ценой и пояснением, коридор, применённые лимиты, предупреждения и итоговая пара «цена до скидки + скидка».

## Акции: авто-вход и авто-выход

Отдельная вкладка **«Акции»** в репрайсере показывает по каждой акции календаря, что приложение
собирается сделать с каждым товаром: **войти**, **остаться**, **выйти**, **не входить** или
**предупредить** («убыточно, но авто-выход выключен»).

### Как принимается решение о входе

1. Считаем плановую цену акции: `planPrice = цена до скидки × (1 − требуемая скидка)`.
2. Считаем экономику по этой цене — с фактическими расходами из отчёта WB, если они загружены.
3. Проверяем три условия: прибыль ≥ 0, маржа ≥ порога (`minMarginInPromoPct`, по умолчанию — целевая маржа),
   цена ≥ минимального порога товара.
4. Считаем **окупаемость входа**: прибыль с единицы в акции падает, поэтому приложение показывает
   «вход окупится, если продажи вырастут хотя бы на N%» и сравнивает с ожидаемым приростом
   (`expectedSalesUpliftPct`, по умолчанию 30%). WB API не отдаёт прогноз продаж в акции —
   это ваша оценка по прошлому опыту похожих акций.
5. Если авто-вход включён — товар входит (цена отправляется в WB + `POST /calendar/promotions/upload`),
   иначе решение показывается как рекомендация.

Прогнозная СПП для расчёта берётся из фактической СПП по продажам (`useForecastSpp`); если прогноз
выключен, вход блокируется — как в INDEEPA.

### Как работает выход из акции

**API Wildberries не даёт исключить товар из акции.** Более того, плановая цена акции считается от
вашей цены до скидки, поэтому «просто поднять цену» не работает — плановая цена поднимется ровно так же,
и товар останется в акции. Автоакции (`type: "auto"`) через API не управляются вообще.

Единственный надёжный способ — **сделать скидку строго ниже порога акции**. Тогда товар перестаёт
соответствовать условиям, и WB выводит его сам. Приложение делает это аккуратно:

* базовую цену **не завышает** (WB следит за «ценой до скидки»);
* скидка опускается до `порог − 1%` (например, при пороге 40% — до 39%);
* если нужная цена при текущей базе недостижима — база **снижается**, чтобы цена для покупателя не прыгала;
* скачок цены ограничен лимитом шага (по умолчанию 19%): выход меняет *структуру* цены,
  а до рабочей цены стратегии товар доезжает обычными пересчётами;
* если товар в нескольких акциях сразу, порог берётся по самой «мягкой» из них — иначе он выйдет
  из одной, но останется в другой;
* если в настройках запрещено менять цену до скидки, приложение выходит при текущей базе
  и честно пишет в причине, что скачок будет большим.

### Очередь возврата цены

После выхода товар попадает в **очередь возврата** (вкладка «Акции» → «Требуют возврата цены»):

| Статус | Что означает |
| --- | --- |
| `ожидает выхода` | WB ещё не вывел товар из акции — ждём |
| `ждёт окончания автоакции` | автоакция подхватит товар обратно, как только цена станет ниже плановой, поэтому цена удерживается повышенной до её конца |
| `готов к возврату` | можно возвращать рабочую цену |

Удержание защищает от «пинг-понга»: движок держит не только цену, но и **скидку ниже порога**
идущей автоакции — одной цены недостаточно, потому что после округления скидки товар может снова
начать соответствовать условиям. Возврат выполняется автоматически по расписанию
(`restorePriceAfterExit`, `restoreAfterAutoPromoEnds`) или кнопкой — в том числе принудительно,
с предупреждением, что автоакция может забрать товар обратно.

## Защита от ошибок

| Риск | Как защищаемся |
| --- | --- |
| Карантин цен WB (новая цена со скидкой ≥3 раза ниже старой) | такие строки помечаются в предпросмотре и **не отправляются** в WB |
| Случайная массовая переценка | любая отправка — только через предпросмотр с таблицей «было → станет» и итогами |
| Уход в убыток | в предпросмотре видны прибыль и маржа после изменения, убыточные строки помечены |
| Слишком резкое изменение | порог «максимальное изменение цены без предупреждения» в настройках |
| Репрайсер уронит цену слишком сильно | лимит изменения за одно обновление (по умолчанию **19%**) и суточный лимит — оба применяются к итоговой цене, красивое округление их не нарушает |
| Репрайсер уйдёт в убыток | минимальная цена коридора + минимальная маржа: ниже пола цена не опускается, а товары в убытке помечаются предупреждением |
| Автообновление без контроля | по умолчанию включён **только расчёт**: автоотправка цен в WB включается отдельным тумблером, каждая отправка пишется в журнал запусков и в историю цен |
| Пересчёт затрёт установленные цены | двухфазный цикл: расчёт сохраняет **предложение** и ничего не меняет, отправка — отдельная фаза (по расписанию или по кнопке) |
| Отправка «вслепую» после чужих правок | перед отправкой цены перечитываются из кабинета: изменившиеся без приложения позиции пропускаются и показываются списком |
| Потеря введённых вручную цен | кнопка «Сохранить» кладёт цену в данные приложения — она переживает перезапуск и обновление из WB и сразу применяется во всех разделах |
| Репрайсер перебьёт цену, которую продавец поставил руками | сохранённая вручную цена важнее расчёта движка: в предложении она помечена `manual: true` и уйдёт в WB вместо цены репрайсера |
| Поток одинаковых ошибок (HTTP 422 по автоакциям) | состав автоакций через API не запрашивается, 422 считается «состав недоступен», одинаковые сообщения не повторяются чаще раза в 8 с |
| Лимиты WB API: 10 запросов / 6 с для цен и 1 запрос / минуту для «Статистики» и «Финансов» | встроенный rate-limiter выдерживает паузы, читает срок повтора из `X-Ratelimit-Retry`, не долбит WB повторами, а раздел, упёршийся в лимит, догружает в фоне и сам сообщает результат |
| Пустой ответ WB принят за успех | «0 строк отчёта» и «статистика на прошлогодних данных» показываются как ⏳ с объяснением причины, а не как ✓ |
| Потеря уже загруженных данных из-за лимита | 429 не стирает ни статистику, ни сохранённые фактические расходы |
| Потеря ключа | ключи шифруются `safeStorage`, есть кнопка удаления |

| Файл | Что внутри |

| `costs.json` | себестоимость и личные расходы по товарам |

| `itemconfigs.json` | личные стратегии, пол и потолок цены по товарам |

| `promojournal.json` | журнал участия в акциях: входы, выходы, возвраты цены |

| `tasks.json` | история отправок цен |
| `stocks.json` | остатки по складам WB |

## Резервные копии и Telegram

### Перенос и восстановление

Откройте **«Настройки → 6. Резервные копии»**:

1. **«Выгрузить всё»** сохраняет один файл `.wbpm.json`: настройки, себестоимости,
   конкуренты, черновики, предложения, истории, акции, остатки и наблюдения витрины.
2. Ключей WB в файле **нет по умолчанию**. Если они нужны для переноса, включите отдельный
   флажок и задайте пароль не короче 8 символов — ключи шифруются паролем. Токен Telegram
   не переносится даже в этом режиме.
3. **«Загрузить»** сначала показывает предпросмотр. По умолчанию локальные конфликтующие
   значения сохраняются. Можно выбрать **«Полная замена»**: появятся число удаляемых данных
   и отдельное подтверждение. Перед применением всегда создаётся копия текущего состояния,
   при ошибке запись откатывается; неверный пароль останавливает весь импорт до записи.
4. Можно включить копирование раз в день/неделю и хранить от 1 до 100 автоматических копий.
   Копии в списке восстанавливаются кнопкой **«Восстановить»** с подтверждением.

В Windows выбор и сохранение идут через системные диалоги; отмена не запускает скачивание
и не применяется как успех. Поддерживаются и ранние `.wbpm.json` из самостоятельного задания J:
предпросмотр предупредит об отсутствии исходных контрольных сумм.

Расписание работает, пока приложение/веб-сервер запущены. Подробности формата и каналов —
[`docs/API.md`, §26.1](docs/API.md#261-выгрузка-и-восстановление-данных--backup).

### Уведомления в телефон

В **«Настройки → 7. Уведомления Telegram»** сохраните токен бота и `chat_id`, выберите события
и при необходимости тихие часы. **«Проверить и отправить тест»** реально вызывает `getMe`
и отправляет сообщение в чат; пустая конфигурация или сбой не показываются как успех.

Доступны уведомления о готовом предложении, успешной/неуспешной отправке, опасном снижении
цены, лимитах WB, старте/окончании акций, новой цене конкурента и низком запасе. Частые события
склеиваются, ночью копятся до конца тихих часов; повторные попытки ограничены. Токен хранится
отдельно от настроек, не возвращается в интерфейс и не включается в резервную копию.
В веб-версии защищайте каталог данных: без системного шифрования Electron секреты хранятся
в резервном режиме Base64, который **не является шифрованием**.

Подробности — [`docs/API.md`, §26.2](docs/API.md#262-telegram--notify).

## Несколько кабинетов WB в одном приложении

Приложение поддерживает **несколько кабинетов WB**: каждый профиль — это имя, ключи и
свой каталог данных `.data/profiles/<id>/` со своими лимитами запросов, ключами и резервными
копиями. Существующий каталог `.data` при первом запуске переносится в профиль по умолчанию
«Основной» без потерь.

1. **Переключатель в шапке.** Когда профилей несколько, в верхней панели появляется список
   кабинетов. Создайте профиль в «Настройки → 5.1 Профили кабинетов WB». Перед переходом
   сохраните изменённые поля: несохранённые правки не переносятся в другой кабинет. При одном профиле
   переключатель не появляется — ничего лишнего делать не нужно.
2. **Раздельные данные и лимиты.** Два профиля не видят данные и ключи друг друга; лимиты
   WB (в том числе жёсткий «1 запрос в минуту» на «Статистику» и «Финансы») считаются на
   каждый кабинет отдельно, а переключение профиля не сбрасывает кэши чужого кабинета.
3. **Собственные секреты.** Ключи каждого профиля шифруются отдельно через `safeStorage`
   в его файле `secrets.enc`, когда шифрование ОС доступно (иначе явно подписанный Base64).
4. **Экспорт/импорт.** Экспорт и импорт профиля идут в формате задания J (`.wbpm.json`,
   тот же, что у резервных копий) — в **«Настройки → 5.1 Профили кабинетов WB»**.
5. **Сводный P&L.** Отдельная вкладка **«Сводка P&L»** показывает локальные финансовые снимки
   с именем кабинета и периодом без запросов в WB. Одинаковые периоды складываются;
   разные периоды или смешанные демо/боевые данные — только отдельными строками с предупреждением.

Веб-версия запускается с профилем, выбранным при старте: `node tools/web-server.js --profile <id>`;
из браузера виден только выбранный кабинет, а остальные не запускают свои фоновые задачи.
Без `--profile` фиксируется выбранный в регистре кабинет на момент старта.
Прогон: `npm run test:profiles` → `tools/checks/profiles-flow.js` + `profiles-safety.js`
(**137 проверок**, включены в `npm test`; на приёмке L было **1591**; после M и доработок — **1713**, UI — 639). Подробности —
[`docs/API.md`, §27](docs/API.md#27-профили-кабинетов-wb--profiles).

## Какие методы WB API используются

| Раздел | Метод | Хост |
| --- | --- | --- |
| Список товаров с ценами | `GET /api/v2/list/goods/filter` | `discounts-prices-api.wildberries.ru` |
| Цены по размерам | `GET /api/v2/list/goods/size/nm` | `discounts-prices-api.wildberries.ru` |
| Установка цен и скидок | `POST /api/v2/upload/task` | `discounts-prices-api.wildberries.ru` |
| Установка цен размеров | `POST /api/v2/upload/task/size` | `discounts-prices-api.wildberries.ru` |
| Состояние загрузки / ошибки | `GET /api/v2/history/tasks`, `GET /api/v2/history/goods/task` | `discounts-prices-api.wildberries.ru` |
| Список акций | `GET /api/v1/calendar/promotions` | `dp-calendar-api.wildberries.ru` |
| Условия акций | `GET /api/v1/calendar/promotions/details` | `dp-calendar-api.wildberries.ru` |
| Товары акции | `GET /api/v1/calendar/promotions/nomenclatures` | `dp-calendar-api.wildberries.ru` |
| Вход в акцию | `POST /api/v1/calendar/promotions/upload` | `dp-calendar-api.wildberries.ru` |
| Продажи / заказы | `GET /api/v1/supplier/sales`, `GET /api/v1/supplier/orders` | `statistics-api.wildberries.ru` |
| Отчёты о реализации (список) | `POST /api/finance/v1/sales-reports/list` | `finance-api.wildberries.ru` |
| Детализация реализации — факт логистики и комиссий | `POST /api/finance/v1/sales-reports/detailed` | `finance-api.wildberries.ru` |
| ~~Детализация реализации (старый метод)~~ | ~~`GET /api/v5/supplier/reportDetailByPeriod`~~ — **отключён WB (404)**, оставлен как фолбэк | `statistics-api.wildberries.ru` |
| Карточки (габариты, объём) | `POST /content/v2/get/cards/list` | `content-api.wildberries.ru` |
| Проверка доступа | настоящие методы категорий (`limit=1`): `/api/v2/list/goods/filter`, `/api/v1/calendar/promotions`, `/api/v1/supplier/orders`, `/content/v2/get/cards/list`, `/api/finance/v1/sales-reports/list` — **`/ping` у WB не существует** | все хосты |

Подробности, форматы ответов и порядок обработки ошибок — в [`docs/API.md`](docs/API.md).

## Структура проекта

```
wb-price-manager/
├─ electron/                  # основной процесс (Node.js)
│  ├─ main.js                 # окно, IPC, шифрование ключей, протокол econ://
│  ├─ preload.js              # безопасный мост (contextBridge) — список разрешённых каналов
│  ├─ service.js              # бизнес-логика: какие данные и откуда брать
│  ├─ wb-client.js            # клиент WB API + rate limiter + понятные ошибки
│  ├─ price-watcher.js        # наблюдатель цен витрины WB: СПП, цена, остаток, конкуренты по SKU
│  ├─ economics.js            # расчёты юнит-экономики (один модуль для Node и браузера)
│  ├─ repricer-engine.js      # движок репрайсера: стратегии, ДЦО, коридор, лимиты (один модуль для Node и браузера)
│  ├─ demo.js                 # демо-магазин: 228 товаров, акции, статистика, конкуренты
│  ├─ store.js                # настройки, себестоимости, черновики цен, предложения репрайсера, история, секреты
│  └─ config.js               # хосты WB, лимиты, имена файлов
├─ src/renderer/              # интерфейс (без внешних библиотек и CDN)
│  ├─ index.html, styles.css
│  └─ js/  app.js · api.js · state.js · ui.js · util.js · views/*.js
│            views/itemcard.js — карточка товара с вкладками (двойной клик по строке)
├─ tools/
│  ├─ serve.js                # dev-сервер для запуска интерфейса в браузере (демо, без входа)
│  ├─ web-server.js           # веб-версия: авторизация, CSRF, CSP, SSE, режимы local/lan/internet
│  ├─ web-auth.js             # сессии и пароль (scrypt + HMAC), блокировка попыток входа
│  ├─ uitest.js               # смоук-тест интерфейса на jsdom
│  └─ checks/                 # прогоны боевого поведения: rate-limit-flow.js (лимиты WB),
│                             #   repricer-flow.js (черновики, две фазы, 422),
│                             #   price-watch-flow.js (наблюдатель витрины),
│                             #   web-server-flow.js (вход, CSRF, SSE, режимы), demo-flow.js, pl-flow.js
├─ docs/                      # API.md (справочник каналов), PRICE-WATCH.md (наблюдатель),
│                             #   GITHUB.md (публикация и deploy-ключ), WEB.md (веб-версия),
│                             #   TASKS-for-agents.md (промты агентам)
├─ Запуск (Windows).bat
├─ Запуск в браузере (демо).bat
├─ Собрать EXE (Windows).bat
├─ Опубликовать на GitHub (Windows).bat
└─ Веб-версия (доступ из сети).bat
```

Интерфейс написан на чистом JS/HTML/CSS — ни одной внешней зависимости, всё работает офлайн, ничего не подгружается из интернета, кроме самих запросов к WB API.

## Безопасность

* API-ключ хранится только на вашем компьютере, шифруется средствами ОС (`safeStorage`), в интерфейс не передаётся.
* `contextIsolation: true`, `nodeIntegration: false`, доступ renderer-процесса — только к явно разрешённому списку IPC-каналов.
* Данные кабинета запрашиваются напрямую у Wildberries, телеметрии нет. Опциональные уведомления идут в Telegram, проверка обновлений — в GitHub Releases; уведомления по умолчанию выключены.
